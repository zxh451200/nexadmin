## A 组：现在不钉，进 schema 之后就改不动

### A1 · `sys_dept` 树形存储方式

**问题**：§12 同时承诺「树形、级联删除」和数据范围「本部门及以下」，但没定存储方式。这个选择进表结构后属破坏性迁移。

**建议补法**（默认方案，可推翻）：`parent_id` ＋ **物化路径 `path`** 双写。

```
| 方案 | 优点 | 代价 | 判 |
|---|---|---|---|
| parent_id only | 简单 | "本部门及以下"要递归 CTE，级联删除要遍历 | ✗ |
| **parent_id + 物化路径 path** | "及以下"= `path LIKE '/1/4/%'` 一次索引扫描；级联删除可批量；三引擎行为一致 | 移动节点要重写子树 path（低频操作） | ✅ |
| 闭包表 closure | 查询最灵活 | 多一张表，每次增删改要维护，生成器复杂度翻倍 | 备选 |
| nested set | 读极快 | 写代价高，部门树是频繁写场景 | ✗ |
```

**验收**：`WITH RECURSIVE` 不出现在框架迁移与热路径查询里；移动部门有单测覆盖 path 重写。

### A2 · 主键策略

**问题**：§7 类型映射把「雪花 ID（应用侧生成）」和「自增主键」并列两行，但没说 `sys_*` 用哪个。`nex add module` 骨架生成器会无所适从。

**建议补法**（这条同时解决 C3 的匹配问题，别拆开定）：

> - **业务表主键统一 `BIGINT` 自增**（框架表与客户表同规则，生成器只认一种）。
> - **出厂数据行不用自增 id 做跨版本匹配**——每行带一个**稳定字符串业务键**（如菜单 `code: 'system:user:list'`、字典 `type + value`、参数 `key`）。对账按业务键匹配，自增 id 只做本地主键。

**理由**：自增 id 跨环境不稳定，一旦拿它做出厂数据对账，"删库重装同形状"这条判据就无从成立（母版仓踩过：种子 id 取确定性值正是为此）。

**验收**：`nex add module` 生成的 model 主键形状唯一；出厂数据对账报告按业务键而非自增 id 输出。

### A3 · 导入导出归属

**问题**：§12 用户模块写了「导入导出」，「明确不做」里没排除，框架件里也没有。

**建议补法**：**框架提供统一 exim 件，模块只注册 provider。**

```
core/exim/                 # 框架区
├── task.go                # 异步任务表 sys_exim_task（状态/进度/错误行回写）
├── template.go            # 模板生成与列定义
└── provider.go            # 模块注册接口：ExportFields / ImportValidate / ImportCommit

modules/system/user/exim.go   # 模块侧只写 provider 实现
```

**理由**：15 个模块各写一套导入导出＝15 套异步任务、15 套错误回写。这是真实复杂度，不是装饰。

**验收**：`sys_exim_task` 只有一张；新增模块的导出能力不写任务表代码。

### A4 · 模块间依赖规矩（"可整目录删"目前不成立）

**问题**：§12 原则 3 说「删目录 ＋ 摘掉 `main.go` 一行注册即下线」，但同一张表里：工作台「聚合各模块统计」、字典被前端下拉渲染、角色分配菜单、部门级联——**删掉 `modules/dict`，用户页的下拉数据源就 500**。

**建议补法**（加进 §12 原则，作为第 4 条）：

> 4. **兄弟模块之间禁直接 `import`。** 跨模块只能走两条通道：① 注册式接口（如 `dict.Provider` 注册到 `core/dict`）② 事件/聚合点（工作台不 import 模块，而是各模块注册 `xxx:stats` 数据源）。
>    配套判据：`scripts/module_deps_check` 扫 `modules/*/` 之间的 import 边，**有边即红**；删模块前跑依赖查询，被引用者给出清单而不是运行时 500。

**验收**：删 `modules/dict` 后，其余模块编译通过、运行时报"字典服务未注册"的**明确降级**，不是 panic/500。

## B 组：文档与目录不一致（便宜，但会被当成不严谨）

### B1 · §4 目录树补全

`modules/` 现在只写 `system/ tenant/ file/`，与 §12 的 15 个模块不符。建议改成：

```
├── modules/                        # ── 框架区 · 可删（删前跑依赖检查，见 §12 原则 4）
│   ├── system/                     #   user role menu dept post dict config
│   ├── notice/                     #   通知公告
│   ├── log/                        #   log-oper log-login
│   ├── online/                     #   在线用户
│   ├── profile/                    #   个人中心
│   ├── file/                       #   文件（本地/OSS/MinIO）
│   ├── tenant/                     #   租户与套餐
│   └── dashboard/                  #   工作台（只注册 stats，不 import 兄弟模块）
```

### B2 · `pkg/` 要么加进目录，要么改措辞

§12「明确不做」写「短信/邮件发送（做成 `pkg/` 能力，不做模块）」，但 §4 没有 `pkg/`。建议补：

```
├── pkg/                            # ── 框架区 · 无路由无表的能力件
│   ├── sms/  mail/  storage/       #   接口 + 多实现，供模块与客户注入
│   └── excel/  idgen/              #   导出编码、ID 生成
```

**判据**：`pkg/` 下任何包**不得**出现 GORM model 或 `Register(r *gin.RouterGroup)`——它是能力不是模块。

### B3 · `web/public` 说明归属

§7 建议单独建 `web/public`（Next.js/Remix），但 §4 没有。二选一并写清：
- **推荐**：标注「公开站属**另仓**，不进框架包」，并从 §4 承诺里摘掉；
- 或加进目录并说明它属框架区还是用户区、升级怎么处理。

（否则 §7 那段"独立部署"与"同一 manifest 契约"自相矛盾——一个 Next.js 站套不进 Go 源码包的所有权分区。）

### B4 · Redis 去留

§12「在线用户：无表，基于 Redis」在 **M1 必带** 列里 ⇒ Redis 成了必选中间件，但 §4 的 `core/` 只有 `database/ storage/`，§2 又主打信创/等保。

**建议**（默认方案）：明写 Redis 为**必选依赖**，补 `core/cache/` ＋ `deploy/` 里的 redis 件 ＋ §7 缓存 key 前缀纪律；若不想引必选中间件，则在线用户改走 DB 会话表 ＋ 令牌黑名单。

**判据**：`docker-compose` 起不来（缺 redis）时，报错要指名"在线用户模块需要 redis"，而不是运行时 panic。

### B5 · `/healthz` 归属

§11 的派生 lane 探 `/healthz`，但 §12 没有健康检查件。建议：`/healthz` 属 **core**（探 DB／Redis／迁移版本），不进 `modules/`，且写进 §12 表格外的「core 能力」清单——和"登录认证不进 modules"同段。

## C 组：母版机制缺件（这三条不补，它仍是好脚手架，不是母版）

### C1 · 定制出口（关掉 P2 最大的洞）

**补在哪**：§6 军规 2 ＋ §4 目录。

**补什么**：军规 2 从"只有 Option"扩成**六类注册式扩展点**：

```
modules/system/user/override.go     # 框架提供注册位，客户写在用户区
```

| 扩展点 | 覆盖的常见定制 |
|---|---|
| `model.field` | 给 `sys_user` 加列（**最高频需求，现在无出口**） |
| `route` | 在既有前缀下挂自定义端点 |
| `menu.item` | 增删改默认菜单项 |
| `dict.type` | 注册新字典类型 |
| `validate.rule` | 替换/追加校验规则 |
| `response.wrap` | 换统一响应包装 |

**关键纪律**：`override.go` 落在**用户区**（`internal/overrides/<module>.go`），框架模块在装配时读取注册，**不改 `modules/` 里的文件**。

**验收**：给 `sys_user` 加一列后，`git diff modules/ core/` **为空**。做不到就是出口不够，补出口而不是补纪律。

### C2 · manifest 加定制意图节

**补在哪**：§5。

```json
{
  "framework_version": "1.3.0",
  "framework_paths": ["core/", "modules/", "pkg/", "docs/", "scripts/", ".github/", "web/src/framework/", "migrations/framework/"],
  "user_paths": ["internal/", "web/src/pages/", "config/", "migrations/business/"],
  "customizations": [
    {
      "id": "cust-001",
      "target": "modules/system/user",
      "kind": "model_field",
      "intent": "工单 #482：用户需归属门店",
      "impl": "internal/overrides/user_store.go",
      "reapply": "automatic"
    }
  ]
}
```

**为什么必须**：`framework_paths` 只能答"这文件归谁"，答不了"客户 1.2 加的那列，1.3 该落到哪"。**文件级冲突检测 ≠ 意图级重放。**

**验收**：`nexadmin customize list` 只读出口存在；升级报告逐条点名 `reapply: manual` 项。

### C3 · 出厂数据三方对账（最难，且 §12 让它必然爆炸）

**问题**：§5 合并策略只覆盖 DDL。但 §12 保证了出厂**行数据**存在——默认菜单、`sys_dict_data`、`sys_config` KV、`xxx:stats` 权限点。客户一定会改，新版本也一定会改。

**补在哪**：§5 之后新增一节「出厂数据与升级对账」。

**补什么**：

```
factory/                    # ── 框架区 · 出厂数据单源（不进 migrations，不进 modules）
├── menus.json  dicts.json  configs.json  permissions.json
└── schema.json             #   形状单源（列/键定义），对账读它
```

- 装配层幂等种入：**空表整棵写、非空零改动**；
- 每行按 **A2 的稳定业务键** 匹配（不是自增 id）；
- 升级时三态：

| 态 | 判据 | 动作 |
|---|---|---|
| 仅出厂变 | 新 factory ≠ base，库内 = base | 自动写入 |
| 仅产品变 | 库内 ≠ base，新 factory = base | 不动 |
| **双方都变** | 两边都 ≠ base | **拒绝自动写**，进人工清单 |

- **禁"以新版本为准覆盖"这一档。** 迁移里也禁写 INSERT/UPDATE/DELETE 与回填（把出厂树焊进迁移＝替每个客户预置一棵他们没要的树）。

**必须写进文档的诚实代价**：**存量库不会因为代码改了出厂形状就自动改形。** 出路只有两条，都要人决定：管理面手排，或清表重种（会丢自定义行）。

**验收**：常驻例现读 `factory/schema.json` ⇔ 种子快照逐行相等；三态各一枚夹具，"双方都变"落在人工清单而不是写入。

### C4 · 契约兼容性闸（让军规 4 有牙）

**问题**：§12 把 OpenAPI 列成 M2「API 文档，触发式开启」——那是**文档功能**。军规 4「一个主版本内不破坏」现在没有任何东西可执行。

**补法**：拆开两件事。
- **契约基线 = 框架必带**：`core/contract/openapi.baseline.json`，发版跑 diff：**删字段／改类型／改必填／改路径 ⇒ 破坏性 ⇒ 主版本号未动则卡发布**；新增为兼容。
- **文档 UI = M2 可选**（Swagger 页面可关）。

**为什么优先级高**：框架改掉 `/api/v1/users` 的分页形状时，**炸的是客户的 `internal/`，而"覆盖框架区"不会警告**——受害者不在框架区。

**验收**：基线里删一个字段 ⇒ 闸红并指名端点与字段。举不出红样例＝闸不存在。

### C5 · 升级要会说"不"

**补在哪**：§5 合并策略之后加 verdict 表。

| verdict | 触发 | 动作 |
|---|---|---|
| `OK` | 无冲突 | 覆盖框架区 |
| `PROTECTED_PATH_MODIFIED` | 客户改了框架区文件 | 存 `.bak` ＋ 变更清单 ＋ **默认不覆盖** |
| `PROTECTED_PATH_UNJUDGED` | **工作树脏**（未 commit） | **不判定**，出路：先 commit 或 reset |
| `FACTORY_CONFLICT` | 出厂数据"双方都变" | 拒绝自动写，进人工清单 |
| `DESTRUCTIVE_MIGRATION` | 迁移含删列/改类型/回填 | 要求显式 `--allow-destructive` |
| `BACKUP_INCOMPLETE` | 备份写入/回读失败 | **中止并回滚** |

**关键**：`PROTECTED_PATH_UNJUDGED` 这一档 P2 现在没有——**分不清"客户改了框架文件"和"客户只是没 commit"，每次升级会误报一片。**

### C6 · §11 派生 lane 补上最关键的断言

现在 §11 证明的是"能编译、能启动"。派生验证真正要证的是母版承诺本身。

**补一步**（放在编译冒烟之后）：

```
5. 在 demo-product 里写 1 条 model_field 定制（给 sys_user 加一列）+ 1 个业务模块
6. nexadmin upgrade 到上一个 tag
7. 断言：定制仍在 · 业务模块零改动 · core/ 与 modules/ 零 diff · 三态对账报告齐全
```

**验收**：这条 lane 红 = 框架不许发版（§11 原纪律，扩到第 7 步）。

## D 组：记录与纪律

### D1 · ADR-lite

**补法**：`docs/adr/NNNN-标题.md`，一页四段：`状态`（accepted / superseded by / retired）· `决策方` · `决策` · `影响面`。

**为什么**：本文已经是三次改判的结果（引擎矩阵、租户豁免、派生 lane 都是新加的），却没有"状态/改判对象"机制。母版的规则会被客户挑战，无记录就腐烂成口头传说，换人接手全部重议。

**判据**：§6 每条军规能指到一份 ADR；每份 `accepted` ADR 在代码或闸里有落点。**两边都不许有孤儿。**

### D2 · i18n 语言清单 manifest 化

**问题**：§7 只有"两层合并"，语言清单仍是代码事实——加第三门语言要动代码。

**补法**：`config/languages.json` 为**唯一来源**；语言切换器选项、`html[lang]`、`html[dir]`、字体栈、`Intl` tag、资源加载路径、后端语言解析**全部从它读，禁硬编码**；语言代码全系统统一 **BCP-47**（前端、后端配置、邮件模板目录、将来内容翻译 `lang` 列同源）。

**验收标准（可直接抄）**：**加一门语言 = 改一个 manifest 文件 ＋ 加若干翻译文件，组件代码零改动，且不需要读任何文档。**

**配套闸**：多语言键集同构（加了中文漏了英文 ⇒ 红）。

### D3 · 审计从"页面"升格为"写路径契约"

**问题**：§12 有操作日志/登录日志，那是**查询页面**。缺的是：谁都能忘记调 log service。

**补法**：
- 写路由**必须**声明审计口，缺 sink ⇒ **挂路由之前**返回错误（不留"路由在、无审计"的半活面）；
- 审计写失败有累计计数，可观测；
- 补 metrics（Prometheus）＋ request id 贯穿。

### D4 · 租户豁免从"文档清单"改成"代码登记＋闸扫"

**问题**：§7 说「平台级表不进租户 scope，清单见 §12」，§12 有一列"租户隔离：否（平台级）"——**表达有了，判据没有**。

**补法**：豁免必须在模型上显式登记（`tenant: none` ＋ 一句理由），闸扫全部模型：**既未嵌租户基座、又未登记豁免 ⇒ 红**。

## 需要你拍板的 5 件事（我给默认值，但这是你的决定）

| # | 决策 | 我的默认建议 | 换向的代价 |
|---|---|---|---|
| 1 | 树形存储 | `parent_id` ＋ 物化路径 | 选闭包表则生成器与迁移复杂度翻倍 |
| 2 | 主键 | 业务表 `BIGINT` 自增 ＋ 出厂行用稳定业务键 | 全上雪花则出厂对账仍需业务键，等于两套都要 |
| 3 | Redis | 明写为必选依赖 ＋ `core/cache/` ＋ 部署件 | 不引则在线用户改 DB 会话表＋令牌黑名单 |
| 4 | 导入导出 | 框架统一 exim 件，模块注册 provider | 每模块自带＝15 套异步任务与错误回写 |
| 5 | 公开站 `web/public` | 划到**另仓**，从本文承诺里摘掉 | 留在框架包就要为 Next.js 站再定一套所有权与升级契约 |
