## 源码插件与授权机制（简述）
插件以源码包交付：安装 = 拷文件 + 重新编译；`edition: free` 不校验授权，`edition: pro` 需要离线签名的授权文件（`data/licenses/<id>.lic`，ed25519 签名，载荷含插件、客户、签发 / 到期时间，可选域名）。

- 命令：`nexadmin plugin list | install | remove | keygen | sign | revoke`（用法见 `nexadmin` 的 usage；`sign` / `revoke` 是发行方用的签发与吊销）。
- 校验：启动时逐个校验，有效才挂载路由和菜单；缺失 / 过期 / 被篡改不挂载，插件管理页显示原因；导入授权后尝试激活已编译插件，须检查 `needRestart` 与日志；热挂载失败、官网根路由或启动期认证扩展等仍需要重启核验，不保证全部热激活。运行中每小时复查一次，到期的插件路由返回 403；到期前 30 天在 `GET /plugins` 里带 `expiresSoon`；授权带 `domains` 时校验当前服务域名（精确或 `*.example.com`，来源见《配置参考》第 8 节）；`requires_nexadmin` 在加载时按框架版本校验；发行方可另发签名的吊销清单 `config/license-revoked.json`，序列号命中的授权状态为 `revoked`（路由返回 403，文件变化后无需重启；辅助手段，买家可删除清单）。
- 运行期启停（`plugin:edit`）：插件管理页每张卡片一个开关，`POST /plugins/<id>/enabled`。停用**立刻**关掉该插件的路由（403 + 原因）与侧栏菜单入口，`GET /plugins/active` 也随之剔除；停用清单落在节点本地的 `data/licenses/disabled.json`，与配置 `disabled_plugins` 取并集（配置优先，被配置停用的插件页面上打不开），重启后保持。**做不到的一侧写清楚**：未实现 `plugin.RestartableStarter` 的 worker（当前所有官方插件）被停用后不会在线重新拉起，重新启用会留 `needRestart=true` 且接口与菜单继续不可用，直到重启服务；已建立的 WebSocket/SSE、事件订阅、作业注册同样要重启才干净停掉。多节点不会自动同步开关状态。
- 约定与开发流程见《plugin-development.md》。该文档末尾“已知限制”一节已与代码行为一致（域名校验、版本范围校验、到期自动下线均已实现）。
- `im`（在线客服，pro）除坐席后台（业务中心 → 在线客服 `/im/conversations`）外，还通过 `/plugins/im/visitor/*` 公开接口为官网右下角客服挂件提供开会话、发消息、增量/翻页拉取、SSE、已读上报、输入中与满意度评价；插件未挂载时该组路由 404，挂件自动隐藏。结束会话会写入一条系统提示消息并同时推到 SSE 与 WebSocket；坐席可认领/转接会话、设置标签、写内部备注（仅坐席可见）、使用快捷回复、发送图片与文件（内容嗅探 + 类型/大小白名单，落 config.storage 指定的 local 或 S3）、按当前筛选导出会话记录（`POST /plugins/im/conversations-export-async`，提交进导出中心；xlsx 双 sheet，任务内上限 5000 行，超过整个任务失败并提示缩小筛选范围）；访客首次打开会话可自动发送欢迎语；访客消息命中敏感词时自动替换为 `***`（坐席消息不过滤）；坐席端带在线心跳（90 秒 TTL），可开启「自动分配」：新会话分给在线且进行中会话最少的坐席，无人在线时排队、坐席上线后按先后领取；会话可统计（可选 7/30/90 天：会话量、平均首响、满意度、按天趋势与坐席工作量）；坐席可撤回自己 2 分钟内发出的消息；可把会话合并进另一个进行中的会话（源会话结束并留合并提示）；已结束的会话被访客再次打开时复用同一行重新开启（清空上一轮的评分与归属，追加「会话已重新开启」系统提示），因此挂件「再发消息会开新会话」与合并后的继续咨询都能正常进行；会话结束后访客可打 1~5 分；超过 24 小时无新消息的会话由插件自动结束；设置里可配置「已结束会话保留天数」，插件每小时清理一次过期会话（连同消息、附件与存储文件）。会话含客户隐私与纠纷证据，删除只开放给超管：单个/批量删除均要求已结束，级联删除消息与附件并记操作日志。坐席端实时通道 WebSocket 优先、SSE（一次性流票）兜底，访客端 SSE + 轮询兜底。访客发消息会给持有 `im:list` 的坐席写一条站内信（分类 `im`，直达会话；同一会话 5 分钟内只提醒一次，坐席正在看该会话时不提醒）。侧栏「在线客服」带未读徽标（`GET /plugins/im/badge`：进行中会话里访客未读的消息条数，与队列每行红点同一口径，已结束会话不计；读到新消息、关闭/删除/合并会话后立即刷新，其余情况随框架 60 秒一轮）；坐席停在客服页时，队列里**任何**会话涨了未读都会弹一条带「查看」的提示（多个会话合并成一条，当前打开的会话交给实时流那一路，不重复提示），页面失焦且开启桌面提醒时再叠加提示音与系统通知。设置里可开启「AI 自动回答」（配合 kb 知识库插件）：未接管的会话由 AI 依据知识库回答（消息发送方 `bot`，坐席端与访客挂件都带 AI 标识）；坐席认领会话或访客点挂件里的「转人工」（`POST /plugins/im/visitor/conversations/:no/handoff`，写会话的 `bot_paused` 标记并发系统提示帧）之后 AI 停答直到会话结束，人工与 AI 不会交替发言；AI 检索不到依据时按设置的兜底话术回复并自动走一次「转人工排队」。接口清单见附录。
- `kb`（知识库，free）是客服 AI 的知识来源与问答编排器（业务中心 → 知识库 `/kb/documents`）：上传 txt / md / pdf / docx 文档（≤2MB）后抽取文本——txt/md 直读、docx 用标准库解 zip 走 XML 流式抽取 `w:t` 文本（页眉页脚脚注不收）、pdf 用纯 Go 的 ledongthuc/pdf 逐页抽文本层（单页字体/CMap 解不开跳过该页继续，抽不出文本的扫描件明确报错引导 OCR，绝不静默入库空文档）——然后按空行分段切块（超长段落在句读处硬切、碎块并入上一块），用系统设置里配置的 Embedding 模型批量向量化（`core/ai` 的 OpenAI 兼容 embeddings，单批 ≤64 条）落 `plg_kb_document` / `plg_kb_chunk`（平台级表；向量存 JSON 文本，检索在应用内存里做余弦 topK，索引按「模型 + 切块数 + 最新更新时间」指纹缓存，文档增删/重嵌立即失效）。文档列表带状态、块数与向量模型；换过 Embedding 模型的旧文档标「需重新向量化」，可一键重跑（也可删除，级联删块）。检索设置（单行 JSON）可调相似度阈值（默认 0.35）与 TopK（默认 4），系统提示模板只能追加风格要求——「只依据资料回答、没有就承认不知道」是写死的硬约束。页面带「测试提问」框：不走 IM 直接看检索命中（文档标题 + 相似度）与模型回答，用于调阈值。AI 自动回答编排器订阅 `im.message.created`：只应答访客消息（防自身回复循环）、会话未被认领且未转人工时，检索 topK 命中则把资料块带标题拼进系统提示调对话模型，以 `bot` 身份回复（meta 记命中来源）；最高分低于阈值一律不编造——按 IM 设置的兜底话术回复并自动转人工排队。多实例用共享缓存对 (会话, 序号) 防重；AI 或模型未配置完整时静默跳过（保持人工现状，不做兜底刷屏）。模型调用统一走 `core.AIGateway`（限流、租户配额与审计同内置 AI 接口），embedding 未配置时上传给出设置指引。插件未挂载时该组路由 404。接口清单见附录。

| 场景 | 结果 | 说明 |
| --- | --- | --- |

仓库里带了一个可复用的厂商租户模拟器：`go run ./scripts/saml-vendor-e2e -base <SP> -admin-user <u> -admin-pass <p>`，按 Okta / Microsoft Entra / Keycloak 三种属性与签名形态各跑一遍登录、角色同步与 SLO（2026-11-09 三档全过）。它直连 ACS、不经过厂商登录页，页面跳转链路由上一段覆盖。

**三家厂商的控制台配置清单（不需要真租户也能照单填）**

- **Okta**：Create App Integration → SAML 2.0；Single sign-on URL 填我们的 ACS，Audience URI (SP Entity ID) 填 SP Entity ID，Name ID format 选 EmailAddress 或 Persistent；Attribute Statements 加 `uid` / `mail` / `displayName`，Group Attribute Statements 过滤组并以 `groups` 输出；SLO 填 SP 登出地址；默认不加密断言，需要在 Okta 侧开启并导入 SP 证书。
- **Microsoft Entra**：Enterprise applications → Single sign-on → SAML；Identifier (Entity ID) 与 Reply URL (ACS) 用 SP 元数据里的值，Logout URL 用 SLO；Attributes & Claims 里 NameID 选 persistent 或 email，若用 claim URI，就把本页属性映射填成对应 URI；也可以直接下载 Federation Metadata XML 粘过来。
- **Keycloak**：Clients → 新建 SAML client；Valid redirect URIs 填 ACS，Client ID 填 SP Entity ID，Name ID format 选 persistent/email；开启 Sign documents 与 Sign assertions，需要加密断言再开 Encrypt assertions；Mappers 加 user property → `uid`/`mail`、group list → `groups`。

三家都先导出或复制「IdP Metadata / Federation Metadata XML」粘过来；只给 URL 就直接填「IdP 元数据地址」。组映射里填厂商实际输出的组值（如 `Everyone`、`Okta Group Name`、`/ops`）。以后真拿到测试租户，配置完跑同一个 `scripts/saml-vendor-e2e` 即可。 |
| RelayState 站内路径深链 | 通过 | 登录后回原页 |

对接三家时按其文档填即可：Okta（app profile 暴露 `uid/mail/groups` 或 OID，ACS 与 EntityID 用 SP 元数据）、Microsoft Entra（NameID 选 persistent/email，属性用 claim URI，SLO 配 Logout URL）、Keycloak（client 勾选 Sign documents/assertions，需要时开加密断言，attributes mapper 输出组）。

1. **起服务**：用一次性库（`NEXADMIN_DATABASE_NAME=<新库>`）起服务；启动即执行 `plugins/saml/migrations` 的 005/007/008，先跑 `migrate --dry-run` 核对待执行清单。
2. **配源**：粘贴测试 IdP 的 EntityDescriptor（自签证书即可），启用后打开「登录时同步角色」并配一条组→角色映射。
3. **首次登录**：走一次 IdP 发起或 SP 发起登录。日志应出现 `saml role sync finished`（`desired/added` 与映射一致）；`sys_user_role` 有对应行，`plg_saml_role_grant` 有 (user, source, role) 记账。
4. **改组**：在 IdP 侧把用户换到另一个映射组后重新登录。日志的 `added/removed` 只能涉及本来源记过的角色；手工分配与其它来源授予的角色必须仍在。
5. **登出**：IdP 分别发一次带 SessionIndex 和不带 SessionIndex 的 SLO。带索引只吊销对应会话，不带索引按 NameID 全量吊销；重复登出不报错。
6. **元数据**：开「签名 SP 元数据」后下载 `?download=1` 的元数据并用 SP 证书验签；配置「元数据签名证书」后，保存未签名元数据必须被拒。
7. **证书**：「导入证书与私钥」换一对自签证书后能重新登录；旧证书 7 天内仍参与解密（prev），到期后不再出现在元数据里。
8. **失败页**：停用源后从 IdP 再跳一次 ACS，浏览器应看到错误页（原因 + 返回登录）；`Accept: application/json` 的请求仍回 JSON。

## 关键词搜索的大小写折算
- 策略：**凡是用户手输关键词的筛选，一律写成 `LOWER(<列>) LIKE LOWER(?)`，两侧都折叠**。原因是方言差：MySQL / MariaDB 这儿的 `utf8mb4` 排序规则不区分大小写，`col LIKE '%Abc%'` 天然能命中；PostgreSQL 的 `LIKE` 区分大小写，所以在这次改动之前，搜索框里带一个大写字母在 PG 部署上静默返回 0 行、在 MySQL 上却搜得到（三引擎都是受支持引擎，不能只按 MySQL 的行为验收）。也不能改用 `ILIKE`——MySQL / MariaDB 没有这个操作符。插件侧的标准写法见 `plugins/report/query.go:423`、`plugins/formbuilder/directory.go:98`、`plugins/im/service.go:507`；内置模块侧是把模式先在 Go 里 `strings.ToLower` 再写成 `LOWER(<列>) LIKE ?`（`modules/system/user/service.go:60-62`、`modules/system/config/service.go:107-109`、`modules/system/dict/service.go:73-78`），折叠发生在绑定值那一侧，口径相同。
- 刻意**不**折叠的豁免（大小写对这些站点无意义，它们匹配的不是人随手打的关键字）：部门的物化路径前缀筛选 `path LIKE ?`，绑进去的值形如 `/1/4/`（`modules/system/dept/scope.go:30`、`modules/system/dept/service.go:167,211,218,221,378`、`modules/system/user/scope.go:55` 的 `dept_id IN (SELECT id FROM sys_dept WHERE path LIKE ?)`、`core/datascope/datascope.go:99`）；官网「缺译文」筛选的 `i18n_json NOT LIKE ?` 匹配的是配置里的语言 code，两侧同源（`plugins/website/service.go:587-589`，已按标注约定写了 `nexadmin:like-exempt` 注释和理由）。注意 IM 的标签包含匹配**不在豁免之列**：`plugins/im/service.go:507` 写的是 `LOWER(CONCAT(',', tags, ',')) LIKE LOWER(?)`，两侧都折叠。
- 约定：确有价值、不受大小写影响的例外，在调用行或其前三行加 `nexadmin:like-exempt` 注释并写明理由（`plugins/website/service.go:587-589` 已按此标注）。已知盲区是把 `LIKE` 片段拼在 `Where` 之外再以变量传入的写法（`plugins/report/query.go` 的 filterSQL），那里要按整句 SQL 人工核对折叠形状。此前这套约定由 `TestPluginsLikeFiltersFoldCase` / `TestLikeCaseFoldGateRepo` 等闸守着（基线：检查 47 条、豁免 11 条、违规 0），用例已随 2026-11-08 清理移除。
