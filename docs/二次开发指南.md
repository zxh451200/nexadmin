# NexAdmin 二次开发指南

给在 NexAdmin 上做二次开发（BI、数字孪生等产品）的团队和 AI agent。目标：开发时不与框架冲突，之后用 `nexadmin upgrade` 无痛升级。
本文随框架升级更新，不要手改；你的业务文档写在别处。给 AI agent 读的精简规则在项目根目录的 `AGENTS.md`（`CLAUDE.md` 是它的副本）。

## 1. 流程全貌

```
nexadmin new → 开发（只写用户区） → git commit → nexadmin upgrade --dry-run → upgrade → 构建测试
```

1. 派生项目：`go run ./cmd/nexadmin new myapp --out ../myapp --module example.com/myapp`。生成的是框架源码 + 空的业务目录（`internal/modules`、`web/src/pages`、`migrations/business`）+ `AGENTS.md`/`CLAUDE.md`。
2. 开发：`go run ./cmd/nexadmin add module article --fields "title:string,status:dict(sys_status)"` 起骨架，再补业务逻辑。先按[快速开始](quickstart.md)完成构建和初始化；开发后端 `go run ./cmd/server`，前端 `cd web && npm install && npm run dev` 默认用 mock，真实联调改用 `VITE_MOCK=false npm run dev`。
3. 升级：先 `git commit`；拿到 release 包（`nexadmin release pack` 产物）或新版源码目录/zip；`nexadmin upgrade --from <路径> --dry-run` 看清单；去掉 `--dry-run` 正式升级；`go mod tidy`、`cd web && npm install`；构建测试；检查 `*.bak` 与输出里的 `WARN`。

## 2. 三类所有权

以项目根的 `.nexadmin.manifest.json` 为准（`framework_paths` / `user_paths`），下表是约定：

| 类别 | 路径 | 升级时 | 你能做什么 |
| --- | --- | --- | --- |
| 框架区 | `core/` `modules/` `pkg/` `cmd/` `web/src/framework/` `migrations/framework/` `docs/` `deploy/` `scripts/` `config/default.yaml` `config/license-keys.pub` `config/license-revoked.json` | 覆盖（后两个由发行方随升级包分发，包里没有则保留现有文件） | 不改。手改的文件升级时存 `.bak` 并 WARN |
| 合并区 | `go.mod` `go.sum` `web/package.json` | 合并：框架包里的依赖覆盖同名条目，你自己加的依赖原样保留 | 新增自己的依赖（精确版本），不改框架已有条目的版本（会被升级改回） |
| 锁文件 | `web/package-lock.json` | 不碰 | 升级后运行 `go mod tidy` 与 `cd web && npm install` 重新生成 |
| 用户区 | `internal/` `plugins/` `web/src/pages/` `web/src/plugins/` `web/src/locales/` `web/src/theme.css` `config/config.yaml` `config/locales/` `migrations/business/` `data/` | 不碰 | 全部业务代码、配置、翻译、迁移 |

吊销清单（`config/license-revoked.json`）与附加公钥（`config/license-keys.pub`）由发行方随升级包分发，升级时按框架区覆盖；吊销清单自带 seq 回退保护（验签通过但 seq 小于当前已采信版本的清单会被忽略并告警，该保护只在进程运行期内生效，重启后以磁盘文件为准）。升级包里没有这两个文件时保留现有文件，不会移入 `.nexadmin-trash/`，`--dry-run` 清单里标为 `K`。

`web/` 下的 `src/App.tsx`、`src/main.tsx`、`src/index.css`、`src/lib/`、`src/vite-env.d.ts`、`public/`、`.env.production`、`.env.development`、`embed.go`、`embed_dev.go`、`vite.config.ts`、`tailwind.config.ts`、`postcss.config.js`、`tsconfig.json`、`eslint.config.js`、`index.html` 也属框架区（以清单为准），同样不要改；`.github/`、`AGENTS.md`、`CLAUDE.md`、`README.md`、`.gitignore`、`.dockerignore`、`.dev-keys/` 在清单里属用户区。

## 3. 定制路径与最小示例

下面说明扩展接口与限制；构建和单元测试不能替代真实环境验收。首次派生、构建与初始化见[快速开始](quickstart.md)。

决策顺序：配置 → 扩展点 → 事件/钩子 → 覆盖页面/停用替换模块 → 向框架提需求；绝不手改框架区。

### 3.1 后端替换内置模块做法：在 `config/config.yaml` 把原模块写进 `disabled_modules`，在 `internal/modules/` 提供**不同 `Name()`** 的替代模块，沿用同样的路由和权限码。
- 同 method+path 被两个模块注册，Gin 在装配路由时直接 panic，所以必须先停用原模块。
- 内置模块和业务模块重名，启动报 `core: duplicate module name`（不是 panic）；替代模块与被停用的模块同名，会被一起停用。
- 替换后验证路由不冲突、权限保持兼容；相关测试入口为 `core/modules_test.go`。

```yaml
# config/config.yaml
disabled_modules: [post]
```
```go
// internal/modules/mypost/module.go（内置岗位模块的路由是 /posts，权限码 post:list 等）
func init() { core.RegisterBuiltin(module{}) }
func (module) Name() string { return "mypost" } // 不能叫 post
func (module) Register(r *gin.RouterGroup, d *core.Deps) {
	r.GET("/posts", core.Perm("post:list"), list(d.DB)) // 沿用权限码，角色已有的授权继续有效
}
```
代价：替换后该模块不再随框架升级。被停用模块的菜单行还在库里（数据），页面要一起覆盖见 3.2。

### 3.2 前端覆盖内置页面做法：在 `web/src/pages/<任意目录>/route.tsx` 导出与内置页相同的 `path`。合并规则：框架 → 插件 → 用户 `pages`，同 path 后者覆盖前者，与文件名顺序无关。
- 规则实现在 `web/src/framework/router/merge.ts`（`discover.ts` 调用它），单测：`cd web && node --test src/framework/router/merge.test.ts`，另有 `npx tsc --noEmit`。
- 覆盖的是整页；实际侧栏菜单来自服务端 `sys_menu`，菜单标题、图标与排序在后台菜单管理维护，不能只改 `route.tsx` 的 `menu`。
- 岗位已并入部门页的第二个标签，旧 `system/post` 只是跳转入口。下面以仍独立的用户页示范。

```tsx
// web/src/pages/my-user/route.tsx
import { lazy } from 'react'
import type { ModuleRoute } from '@/framework/router/types'

export const routes: ModuleRoute[] = [
  { path: 'system/user', component: lazy(() => import('./MyUserPage')), perm: 'user:list' },
]
```

### 3.3 i18n
做法：前端把同名 key 写进 `web/src/locales/zh-CN.json` 与 `en-US.json`；后端文案写 `config/locales/<lang>.yaml`。
- 前端合并顺序：`web/src/framework/**` → `web/src/plugins/**` → 其余（`web/src/locales`、`pages/**/locales`），同名 key 后者覆盖前者。顺序由 `i18n/init.ts` 显式控制。语言清单落库后以 `sys_language` 为准，由平台超管在「系统设置 → 高级 → 语言」维护，YAML 仅播种空表。源码字典与 `docs/` Markdown 都需重新构建部署；公开站语言集合或前缀变化需要重启。文档按稳定 Code 定位：`zh-CN` 用中文源、英文用 `en/`、其他语言用小写主段，不跟随 URL prefix 改目录。营销内容用官网 CMS，不复制技术文档。
- 后端 `core/i18n.New` 先载入内置语言包，再用 `config/locales/*.yaml` 同名覆盖。

```json
{ "user": { "menu": "成员管理" } }
```

### 3.4 菜单- 二开模块的菜单由 `add module` 生成的种子写入，重启补齐。
- 内置菜单改名/隐藏/排序：由平台超管在后台「菜单管理」维护。通用种子按业务键补缺，不覆盖自定义值；版本兼容修复可能识别旧的出厂值进行迁移，升级前仍应检查菜单与路由兼容说明。
- 菜单硬删除，下次启动种子会按业务键补回（菜单表无软删除）。要藏起来请停用或设为隐藏，不要删除。
- 侧边栏只显示前端有对应路由的菜单，隐藏/停用/无权限的节点都不出现（`buildMenuFromServer`）。

### 3.5 主题与品牌- 品牌色：在 `web/src/theme.css` 的 `:root {}` 里只写要改的变量，它在 `index.css` 里最后引入，覆盖 `framework/theme/tokens.css`。暗色主题的变量写在 `.dark {}` 里。
- 站点名、logo：后台「系统设置」（站点名 `siteName`、`logoUrl` 存数据库），不改代码。

```css
:root { --primary: 160 84% 39%; } /* tokens.css 里 --primary 是 H S% L% 三元组 */
```

### 3.6 配置做法：只在 `config/config.yaml` 写要改的项；`config/default.yaml` 随升级覆盖。`core/config.Load` 先读默认值再 `MergeInConfig` 合并用户文件，`NEXADMIN_*` 环境变量优先级最高。map 逐键合并，列表整体替换（如 `disabled_modules`；`languages` 要写全且仅用于语言空表播种，之后以 `sys_language` 为准）。

```yaml
ratelimit:
  login: { limit: 5, window: 1m }   # 只改登录限流，其余沿用默认
```

### 3.7 后端扩展点（逐项）
| 需求 | 做法与最小例子 | 结论 |
| --- | --- | --- |
| 事件订阅 | `event.Subscribe(event.SubscriberFunc(func(e event.Event){ if e.Name == event.UserCreated { ... } }))`，写在你模块的 `Register` 里。Handle 在分发协程串行执行，要快；队列满会丢事件 | 支持 |
| 异步任务 | `job.Register("report.export", handler)`，提交用 `job.Default().Submit(ctx, job.Submit{Type: ..., Owner: uid})`；同类型重复注册后者覆盖前者 | 支持 |
| 操作日志 | 通过 `core.Deps` 的 `d.OperLogMiddleware("article", "create")` 挂写路由，不直接依赖内置 log 模块。提供方未注册或被停用时不记日志；须核验模块注册顺序与实际记录 | 支持 |
| 权限点 | `core.Perm("article:list")` 登记并鉴权；前缀用自己的模块名。新权限点超管默认拥有，其他角色到「角色管理」分配 | 支持 |
| 限流 | `middleware.RateLimit(d.Cache, d.Log, "my-scope", middleware.ByUser(), 60, time.Minute)`，超限 429；缓存故障时放行 | 支持 |
| 统一响应与错误 | `response.OK / Page / Fail`；错误 `response.BadRequest("biz.title_empty")`，key 的文案写在 `config/locales/<lang>.yaml`，找不到 key 时原样返回 key | 支持 |
| 数据范围 / 角色分配校验 | `nexadmin/core/datascope`（按操作者数据范围裁剪查询、`Resolve` 取范围）与 `nexadmin/core/roleassign`（分配角色三道校验）是公开包，业务模块可直接导入；用法参考 `modules/notice/scope.go`、`modules/system/user/roleguard.go` | 支持 |
| 换租户解析 / 域名映射 / 登录提供者 | 在用户区的 `internal/boot/boot.go` 的 `Options()` 里返回 `core.WithTenantResolver(...)` 等 Option，`cmd/server/main.go`（框架区）会追加它们，不需要改 main.go | 支持 |
| 自定义登录方式 | 模块实现 `auth.Provider` 即被 `core` 自动收集（第一个生效） | 支持 |
| 导入中心的数据源 | 模块实现 `importspec.Provider`（`ImportSources(db *gorm.DB) []importspec.Source`，契约在 `nexadmin/pkg/importspec`）即被自动收集，**不用改导入中心或框架、也不用在别处登记**；要按运行时条件决定来源时，才在 `Register` 里调 `imports.RegisterSource`。契约放中立包，提供方不必反向依赖导入中心插件。插件只做解析、模板、台账与错误报告，逐行落库由 `Handler` 负责：`Required` 列空白整行失败，返回 error 即记入错误报告。`TitleKey`/`LabelKey` 有值时来源标题与模板表头随请求语言渲染，解析时会识别全部已配置语言的表头（切语言上传不丢列）。出厂示例见 `plugins/crm/import.go`（客户导入）与 `modules/system/dict/importsource.go`（字典数据导入，框架内置模块同样可实现，不构成反向依赖）。注意大文件走异步协程、跑在 `context.Background()` 上，**拿不到请求级租户**，租户表要先自行处理租户上下文 | 支持 |

### 3.8 前端 ESLint 规则在二开项目里是否生效（部分）
`web/eslint.config.js` 随项目拷贝，`npx eslint src` 对 `src/pages/**` 生效：直接引用 `@/framework/ui/table|dialog|sheet|drawer`、写死十六进制色值或 `bg-blue-500` 色阶类，都会出现警告。注意：全部是 `warn`，不会让构建失败；`web/src/plugins/**` 不在“直接引用原语”规则范围内。要把警告当门禁，在 CI 里用 `npx eslint src --max-warnings 0`，或让 AI agent 自查时必须清零。

### 3.9 往工作台加卡片做法：在任意模块目录放 `cards.tsx`，导出 `cards: DashboardCard[]`，工作台自动发现，**不用改框架的工作台页面**。发现范围：`web/src/framework/modules/*/cards.tsx`、`web/src/plugins/*/cards.tsx`、`web/src/pages/**/cards.tsx`（目录不存在或为空不报错）。二开项目把卡片放在 `web/src/pages/<模块>/cards.tsx`。

```tsx
// web/src/pages/my-order/cards.tsx
import { lazy } from 'react'
import type { DashboardCard } from '@/framework/modules/dashboard/types'

export const cards: DashboardCard[] = [
  {
    id: 'my-order-today', // 全局唯一，建议「模块名-含义」
    title: 'myOrder.card.today', // i18n key，编辑布局时也显示它
    perm: 'myOrder:list', // 没有权限码则所有登录用户可见
    size: 'sm',
    order: 300,
    component: lazy(() => import('./TodayOrdersCard')), // 卡片自己拉数据（react-query）
  },
]
```

规则：
- 字段：`id`（最长 64，只允许 `[a-z0-9-_.]` 且以字母或数字开头，不合法的卡片被忽略）、`title`（i18n key）、`perm?`、`size`（`sm`/`md`/`lg`/`full`：桌面 md 起占 1/4、1/2、3/4、整行；手机一律整行）、`order?`（默认顺序，小的在前；不写排在有值的后面）、`component`（建议 `React.lazy`）、`defaultHidden?`（新卡片初始隐藏）。
- 覆盖：同 `id` 时优先级 框架 < 插件 < 用户页面，后者覆盖前者（与路由一致）；在 `pages` 里声明内置卡片的 id（如 `dashboard-stats`）即可替换它。规则实现在 `web/src/framework/modules/dashboard/merge-cards.ts`。
- 权限：按当前用户权限过滤（`checkPerm`，与路由 `perm` 判定一致）；没有权限的卡片既不显示，也不出现在「编辑布局」里。
- 个人布局：用户在工作台「编辑布局」里拖动/上移下移/隐藏卡片，布局按用户保存到后端（`GET/PUT/DELETE /dashboard/layout`，表 `sys_dashboard_layout`，只读写自己的）。合并规则 `mergeLayout`（`dashboard/layout.ts`）：保存顺序里仍存在的按保存顺序；不再存在的 id 丢弃；新出现的卡片（升级或新装插件带来的）追加到末尾并按 `order` 排序；`defaultHidden` 的新卡片初始隐藏。服务端不校验 id 是否存在。
- 单测：`cd web && node --test src/framework/modules/dashboard/*.test.ts`。
- 本版不提供自由摆放与缩放；`add module` 不生成 `cards.tsx`，需要时手写。

## 4. 常见冲突场景与解决

| 场景 | 现象 | 解决 |
| --- | --- | --- |
| 改了框架文件 | 升级输出 `WARN: 被手改过`，旧内容在 `<文件>.bak` | 对比 `.bak` 与新文件，把改动迁到用户区（第 3 节的扩展点、覆盖页面或替代模块），再删 `.bak`；不要把旧内容拷回框架文件 |
| `go.mod` / `package.json` 冲突 | 升级后依赖版本不一致或多出冗余条目 | 以框架的条目为准，补回自己新增的条目，`go mod tidy`、`npm install`；自己的依赖用精确版本且别和框架已有条目重复 |
| 菜单与权限 | 新菜单只有超管可见；内置菜单被删后又出现 | 新菜单到「角色管理」分配；内置菜单用隐藏/停用，不要删（种子按业务键补缺） |
| 迁移 checksum 报错 | 启动拒绝，提示已执行的迁移文件内容变了 | 还原该文件，把结构变更写进下一个编号的新 SQL。手工修好库后用 `nexadmin-server migrate --mark-applied <scope>/<文件名>` 标记（`migrate --status` 先看状态） |
| 插件与业务模块重名 | 启动报 `core: duplicate module name "xxx"` | 业务模块改 `Name()`（同时改权限码前缀和表前缀）；插件的表前缀是 `plg_<id>_`，业务表用 `biz_` |
| 业务表与框架冲突 | 表名撞 `sys_` / `plg_` | 业务表一律 `biz_` 前缀 |
| 删示例模块后编译失败 | `internal/modules/modules.go` 里有悬空导入 | 删目录的同时删掉那一行 `_ ".../internal/modules/example"` |

## 5. 给 AI agent 的使用方式

1. 把项目根的 `AGENTS.md` 交给 agent（Claude Code 读 `CLAUDE.md`，内容相同）。开发前让它先读 `.nexadmin.manifest.json` 与本指南第 3 节。
2. 派发子 agent 时，把 `AGENTS.md` 第 9 节的固定前缀原样放在每个任务 prompt 开头（子 agent 没有主会话的上下文，不写就会遗忘）。
3. 要求 agent 遇到“框架没有的能力”时停下汇报，不要手改框架区。
4. 每次任务结束让它跑：`go build ./... && go vet ./...`，前端 `cd web && npx tsc --noEmit`。
5. 升级前后各让 agent 对照 `git diff --stat` 确认只动了预期目录。

固定前缀（与 `AGENTS.md` 第 9 节一致）：

```
你在 NexAdmin 二开项目里工作。目录所有权：框架区（core/ modules/ pkg/ cmd/ web/src/framework/ migrations/framework/ docs/ deploy/ config/default.yaml）绝不修改；
go.mod、go.sum、web/package.json 只能新增自己的依赖（精确版本），不改已有条目；其余代码只写在 internal/、web/src/pages/、web/src/locales/、web/src/theme.css、config/config.yaml、migrations/business/。
需要框架没有的能力时停下并汇报缺口，不要手改框架区。后端模块在自己包的 init() 里 core.RegisterBuiltin，不改 main.go；业务表前缀 biz_，迁移只增不改；只使用 AGENTS.md 里列出的 nexadmin 命令。
前端：用 framework 页面骨架（AppLayout/DataTable/FormLayout/ResponsiveDialog），移动优先；颜色只用语义 token；方向用逻辑类（ms-/me-/ps-/pe-/text-start）；文案进 web/src/locales 的 zh-CN 与 en-US 两份；业务内容要多语言时用 web/src/framework/components/i18n（整表换语言 + 按语言发布），不要自己按语言克隆字段；先写 *.mock.ts 让页面跑通再接接口。
完成标准：go build ./...、go vet ./...、cd web && npx tsc --noEmit 通过；汇报时列出新增/修改的文件。
```
