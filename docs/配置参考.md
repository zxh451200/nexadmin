# NexAdmin 配置参考

本文逐项列出 `config/default.yaml` 的全部配置键。内容来自 `config/default.yaml`、`core/config/config.go`、`core/config/providers.go` 与各消费方代码；表格初稿由脚本从 default.yaml 展开，说明列经人工对照代码核对。

## 1. 加载规则

- 读取顺序：`config/default.yaml`（框架区，随升级覆盖）→ `config/config.yaml`（用户区，不存在则忽略）→ 环境变量。后者覆盖前者。
- 合并方式：map 逐键合并，列表整体替换（`disabled_modules`、`languages`、`auth.methods`、`server.cors_origins`、`server.trusted_proxies` 要写全）。
- 路径相对进程工作目录：配置、`data/`、`logs/`、`config/locales/`、`migrations/` 都按当前目录找，所以服务要在项目根目录（或等价布局的目录）启动。`data/` 与 `config/locales/` 目录名固定，没有对应配置项。
- 环境变量写法：前缀 `NEXADMIN_`，键名转大写，`.` 换成 `_`。例：`server.port` → `NEXADMIN_SERVER_PORT`，`database.password` → `NEXADMIN_DATABASE_PASSWORD`，`ratelimit.login.limit` → `NEXADMIN_RATELIMIT_LOGIN_LIMIT`，`ratelimit.pat_create.window` → `NEXADMIN_RATELIMIT_PAT_CREATE_WINDOW`。
- 环境变量类型：整数、布尔、时长（`45m`、`2h`）、逗号分隔的列表（`NEXADMIN_DISABLED_MODULES=post,notice`、`NEXADMIN_SERVER_CORS_ORIGINS=https://a.com,https://b.com`、`NEXADMIN_AUTH_METHODS=password,phone`）。`languages`（对象列表）和 `auth.providers`（map）用环境变量覆盖：未验证，建议写在 `config.yaml`。
- `${ENV}` 引用：`auth.providers.*` 的字符串字段里的 `${NAME}` 展开为环境变量，变量未设置时得到空串（该 provider 视为未配置）；`storage.s3.*` 的字符串字段同样展开，但变量未设置会报 `config: environment variable NAME is not set`。其他键不展开 `${}`。
- 启动时的校验（`core/config` 的 `validate`）：`app.env` 只能是 `dev` / `production`；`server.port` 1–65535；`database.type` 只能是 `mysql` / `mariadb` / `postgres`；`database.node_id` 0–1023；`cache.driver` 只能是 `memory` / `redis`，redis 必须有 `cache.addr`；`languages` 不能为空；`auth.access_ttl`、`auth.refresh_ttl` 必须为正；`storage.driver` 只能是 `local` / `s3`，s3 必须有 endpoint、bucket、access_key、secret_key；`backup.schedule` 为空或 `HH:MM`；`backup.keep_days`、`backup.keep_count` 不能为负。校验失败的报错形如 `config: server.port 99999 out of range`。

## 2. app / server / database / cache

| 键 | 类型 | 默认值 | 作用 | 何时需要改 |
| --- | --- | --- | --- | --- |
| `app.env` | string | `dev` | `dev` 或 `production`。production：Gin release 模式、日志输出 JSON 到 stdout 和 `logs/nexadmin.log`、CORS 只放行白名单、`reinit` / `restore` 额外要求输入库名确认；dev：控制台日志，CORS 放行任意 Origin | 正式环境必须设为 `production` |
| `app.name` | string | `NexAdmin` | 日志 / 默认名称用途。向导会把站点名同时写入这里，但登录页、顶栏、PWA manifest 显示的站点名取自设置页「站点」分区的 `siteName`（`sys_setting`，向导和 `init --config` 都会写入它，之后在设置页修改） | 无需改 |
| `app.timezone` | string | `UTC` | IANA 时区名。工作台统计、日志、备份定时（`backup.schedule`）、AI 提示里的“今天”读取它；向导会校验并写入所选时区 | 按业务所在时区 |
| `app.auto_migrate` | bool | `true` | 已初始化服务启动时控制平台库自动迁移；租户库还要求 `database.isolation.auto_migrate=true`。关闭自动迁移时仍检查待迁移项，有待执行项则拒绝启动，需先运行 `nexadmin-server migrate` | 生产想把升级与启动分开时设 `false` |
| `server.port` | int | `8080` | HTTP 监听端口（监听 `:port`，所有网卡） | 端口冲突或容器映射 |
| `server.cors_origins` | list | `[]` | 允许跨域的 Origin 白名单，精确匹配，不支持 `*`；空表示同源。dev 环境不看白名单，放行任意 Origin | 前端与后端不同源部署时 |
| `server.trusted_proxies` | list | `[]` | 可信反向代理的 IP / CIDR 列表（可用环境变量 `NEXADMIN_SERVER_TRUSTED_PROXIES=127.0.0.1,10.0.0.0/8`）。空 = 不信任任何代理，真实客户端 IP 只取 TCP 对端地址，伪造的 `X-Forwarded-For` / `X-Real-IP` 无效；非空 = 仅当对端地址在列表内才采信这两个头，并取其中最右一个不在列表内的地址。限流、登录 / 操作日志 IP、在线会话、开放应用 IP 白名单用它；初始化向导的本机判定、`/metrics` 回环判定、本机关停接口永远只看对端地址，不受它影响。每项必须是合法 IP 或 CIDR，否则启动报 `config: server.trusted_proxies has invalid IP/CIDR ...` | **反向代理（nginx / 负载均衡）部署必须配置**，否则所有用户共用代理地址的限流额度；写得过宽会让别人伪造来源 IP |
| `database.type` | string | `mysql` | `mysql` / `mariadb` / `postgres`（向导里的 `postgresql` 会写成 `postgres`） | 按实际库 |
| `database.host` / `database.port` | string / int | `127.0.0.1` / `3306` | 数据库地址 | PostgreSQL 常用 5432 |
| `database.user` / `database.password` | string | `root` / 空 | 数据库账号；密码不进日志，向导写入 `config.yaml` 时文件权限为 0600 | 生产用环境变量传密码 |
| `database.name` | string | `nexadmin` | 库名；向导里可勾选“库不存在则自动创建” | 按实际库 |
| `database.node_id` | int | `0` | 雪花 ID 节点号 0–1023，或 `-1` = 自动选号。多实例必须各不相同；redis 缓存下启动时用带 TTL 的租约检测重复，被别的存活实例占用则拒绝启动（`memory` 缓存下不检测），详见《部署与运维指南》第 10 节。`-1`（2026-10-28 起）：启动时在共享缓存上按 0–1023 顺序抢占第一个空闲号（SET NX + TTL 续约，语义与手工模式一致），全占用则拒绝启动；**自动选号必须配共享缓存**，`memory` 缓存下配 `-1` 直接启动失败 | 多实例部署填 `-1` 可免去手工错号；单实例保持 `0` |
| `cache.driver` | string | `memory` | `memory`（进程内）或 `redis`（Valkey 兼容）。令牌吊销、验证码、登录失败锁定、限流计数、在线会话都存在缓存里 | 多实例部署应使用 `redis` |
| `cache.addr` / `cache.password` | string | 空 / 空 | redis 地址（如 `valkey:6379`）与密码；`driver=redis` 时 addr 必填，连不上启动报错 `cache: redis/valkey at <addr> is unavailable` | 使用 redis 时 |

### 2.1 database.isolation（可选，默认不启用）

字段由 `core/config/config.go` 定义，连接池和表边界由 `core/database/isolation.go` 校验。当前默认示例仅含注释；下列内容是配置格式说明，未写入现有部署配置。

| 键（均在 `database.isolation` 下） | 默认 / 回落值 | 作用 |
| --- | --- | --- |
| `enabled` | `false` | 开启服务器显式配置的租户业务库路由；不会自动拆分、搬迁存量数据 |
| `auto_migrate` | `false` | 已初始化服务启动时，只有它与 `app.auto_migrate` 都为 `true` 才执行租户迁移；否则检查，有待迁移则拒绝启动。向导 / `init` 显式执行平台迁移，租户部分仅按此项执行或检查；手动 `migrate` 不受这两个自动开关限制 |
| `max_pools` / `max_open` / `max_idle` / `lifetime` | `16` / `10` / `0` / `30m` | 前两项及 lifetime 为 0 时使用回落值；配置租户数不得超过 max_pools，max_idle 不得超过 max_open |
| `tables` | 空 | 必填租户业务表清单；不能以 `sys_` 开头，不能与平台表重叠 |
| `platform_tables` | 空 | 在内置控制面表之外补充平台表；必须与实际模型及 SQL 表名一致 |
| `tenants` | 空 | 必填连接 map；键为无前导零的正十进制租户 ID，值含 `type`、`host`、`port`、`user`、`name`、`password_env` |

配置形状示例（仅供将来按实际业务填写，不可直接作为已验收配置使用）：

```yaml
database:
  isolation:
    enabled: false
    auto_migrate: false
    max_pools: 16
    max_open: 10
    max_idle: 0
    lifetime: 30m
    tables: [biz_order]             # 替换为真实业务表，不能留空启用
    platform_tables: []            # 启用 assistant 时加入 plg_assistant_conversation，见下方
    tenants:
      "123":
        type: mysql                # 必须与平台库归一化后的引擎一致
        host: db-tenant.example.com
        port: 3306
        user: tenant_app
        name: tenant_123
        password_env: TENANT_123_DB_PASSWORD
```

`password_env` 是环境变量名，运行时必须存在且非空；连接信息不来自租户表。平台与各租户连接目标须不同。内置认证、组织、运营等 `sys_*` 控制面表仍在平台库，带 `tenant_id` 也不意味着迁入独立库；只有 `tables` 中的业务表路由到租户库。未知表、不能证明单库边界的原生 SQL / join、跨库操作会被拒绝；业务和插件迁移必须明确 platform / tenant 目标。备份恢复及 `migrate --tenant` 的范围见《部署与运维指南》。

assistant 清单声明 `migration_target: platform`。启用该插件并使用独立库隔离时，应在 `platform_tables` 中加入 `plg_assistant_conversation`，不能放进租户业务 `tables`。Go 模型、三引擎 SQL 与 PostgreSQL 索引的表名统一为 `plg_assistant_conversation`；Go 实体主键 `id` 为 `string`，由 `newID()` 使用 `crypto/rand` 生成 16 字节，再以 `hex.EncodeToString` 编码为 32 位小写十六进制字符串，SQL 类型为 `CHAR(32)`；入口由 `validConversationID` 检查长度与 `0–9`、`a–f` 字符集，不使用 `pkg/idgen` 或雪花 ID。所有会话查询显式带 `tenant_id` 与 `user_id`。开发期（框架 0.1.0 未发布）直接修正了 001 迁移，已执行过旧 001 的开发库需手工删表重建。瞬态 run/lease 同样使用随机 ID。sqlmock 单测覆盖创建、列表、读取与租户/用户隔离；本次仅核对代码并修正文档，未执行测试或真实数据库 SQL，增加配置不等于表已建立。

### 2.2 MCP 的缓存依赖

MCP 会话元数据和每会话四个并发槽位存入配置的缓存，要求实现原子 `cache.Locker`；多实例须共享 Redis / Valkey，`memory` 仅本进程可见。初始化返回 `Mcp-Session-Id`，会话固定有效期不超过 15 分钟且不超过初始化凭据到期时间，活动和凭据刷新不续期；会话绑定用户、租户及具体凭据，不能替代登录。每实例最多跟踪 1024 个会话、64 个并发请求；这些是代码常量，不是 YAML 配置键。每请求最长 30 秒，并受凭据和会话到期时间约束。缓存异常拒绝会话请求；凭据变化后应重新初始化。协议及写确认边界见《功能与权限清单》。

## 3. languages / auth / sms

| 键 | 类型 | 默认值 | 作用 | 何时需要改 |
| --- | --- | --- | --- | --- |
| `languages` | list | `zh-CN`（默认）、`en-US` | 仅在 `sys_language` 为空时播种；每项可含 `code, name, dir, default, short, htmlLang, ogLocale, prefix, dateFormat`。落库后语言切换、协商与官网都以 `sys_language` 为准，改 YAML 不覆盖已有清单 | 已初始化系统由平台超管在「系统设置 → 高级 → 语言」维护；语言集合或 prefix 变化需重启。源码字典和 Markdown 修改需重新构建 |
| `auth.methods` | list | `[password]` | 登录方式：`password`、`phone`。`phone` 还要求 `sms.provider` 非空，否则自动隐藏 | 启用手机号登录 |
| `auth.providers` | map | `{}` | 第三方登录，键为 `wecom` / `dingtalk` / `feishu` / `google` / `github` / `oidc`；缺 `client_id` / `client_secret` / `redirect_uris` 视为未配置，登录页不显示，也不报错。`wecom` 还要 `agent_id`；`oidc` 要 `issuer`，或同时给 `auth_url`、`token_url`、`jwks_url`。字段见 3.1 | 启用第三方登录 |
| `auth.proxy` | string | 空 | 第三方登录、短信等出站请求使用的 HTTP(S) 代理；空为直连 | 服务器访问不了 Google / GitHub 时 |
| `auth.jwt_secret` | string | 空 | JWT 签名密钥，至少 32 字符。空则首次启动自动生成并保存到 `data/jwt.secret`（权限 0600） | 多实例必须所有实例一致（共享该文件或显式配置） |
| `auth.access_ttl` | duration | `30m` | access token 有效期，必须为正 | 按安全要求 |
| `auth.refresh_ttl` | duration | `168h` | refresh token 有效期（闲置窗口的回退值），必须为正。后台「设置 → 安全」的「闲置自动退出」优先（`0` = 用本值）；「最长会话」同在该分区，登录与刷新时实时生效 | 按安全要求 |
| `auth.single_session` | bool | `false` | 开启后仅接受该用户最近一次登录签发的令牌；刷新使用原子比较替换，旧会话不能抢回新登录。启用前的令牌需重新登录。多实例须配置一致、共享 Redis，缓存必须实现 `cache.Lease`，异常时拒绝放行 | 要求单账号单会话时 |
| `auth.allow_register` | bool | `false` | 自助注册开关：开启后登录页出现注册入口（`POST /auth/register`）。注册强制图形验证码（与登录同款，绑定 IP、一次性）并按 IP 限流（每小时 10 次）；用户名规则同向导超管（字母开头，3-32 位字母/数字/下划线）；注册进当前解析到的租户（无域名绑定时为默认租户）并受该租户套餐用户数上限约束；成功发布 `user.created` 事件 | 开放自注册的对外部署 |
| `auth.register_roles` | list | `[]` | 注册用户默认挂的角色码（在当前租户内解析，如 `[guest]`）；配置了但任一角色不存在时注册整体拒绝（不静默降权）。空 = 不挂角色，注册后能登录但侧边栏为空，待管理员在用户管理里分配 | 给注册用户默认权限 |
| `sms.provider` | string | 空 | 短信通道：空（不启用）、`log`（仅开发）、`webhook`、`aliyun`、`tencent` | 启用手机号登录 / 绑定手机号 |
| `sms.template` | string | `login` | 验证码模板标识：阿里云填审核通过的 TemplateCode（变量 `${code}`）；webhook 原样放进请求体的 `template` 字段 | 用阿里云时 |
| `sms.webhook.url` / `sms.webhook.secret` | string | 空 / 空 | webhook 通道：POST JSON 到你的网关，带 `X-Timestamp` / `X-Nonce` / `X-Signature: sha256=<hex>`，签名为 HMAC-SHA256(secret, timestamp + "." + nonce + "." + body) | `provider=webhook` 时 |
| `sms.aliyun.access_key_id` / `access_key_secret` / `sign_name` / `endpoint` | string | 空 | 阿里云短信（Dysmsapi）；`endpoint` 空则 `https://dysmsapi.aliyuncs.com`；建议用只有短信权限的 RAM 子账号 | `provider=aliyun` 时 |

腾讯云短信：`sms.tencent.secret_id`、`secret_key`、`sdk_app_id`、`sign_name` 为必填凭据，支持环境变量引用；`region` 默认 `ap-guangzhou`，`endpoint` 默认 `https://sms.tencentcloudapi.com`。验证码模板使用 `sms.template`，通知使用 `sms.tencent.notify_template`（空则跳过通知短信）。`sms.tencent.param_order` 按模板 ID 指定变量顺序，如 `"123456": [code]`；未指定时按参数名排序，多参数模板必须核对顺序。实际发送需通过腾讯云审核的签名、模板和短信权限。

### 3.1 auth.providers.<name> 字段

| 字段 | 说明 |
| --- | --- |
| `client_id` / `client_secret` | 应用凭据；企业微信 client_id=CorpID、client_secret=应用 Secret；钉钉为 AppKey / AppSecret；飞书为 App ID / App Secret。用 `${ENV}` 引用环境变量，不要明文写进仓库 |
| `redirect_uris` | 回调地址白名单，精确匹配，等于前端回调页 `/admin/login/oauth/<provider>` 的完整 URL |
| `match_by` | 首次登录自动匹配已有账号的依据：`phone` / `email` / `employee_no`，空为不自动匹配。`email` 只认已验证邮箱；`employee_no` 对应本地用户名；匹配不上提示“绑定已有账号” |
| `auto_create` | 匹配不上时自动建号（无密码），默认 `false` |
| `default_role` | `auto_create` 赋予的角色编码，空时用 `guest`；内置角色不会被自动赋予 |
| `allowed_email_domains` | 只允许这些邮箱域名登录（要求邮箱已验证），默认不限制 |
| `agent_id` | 仅企业微信，必填 |
| `issuer` / `name` / `scopes` | 仅 `oidc`（`google` 可用 `issuer` 覆盖）：issuer 需提供 `/.well-known/openid-configuration`；`name` 为登录页展示名 |
| `auth_url` / `token_url` / `userinfo_url` / `jwks_url` | 一般不用配；`oidc` 无 discovery 时手工指定 |

## 4. upload / storage / message / job / export / setup / ai / disabled_modules

| 键 | 类型 | 默认值 | 作用 | 何时需要改 |
| --- | --- | --- | --- | --- |
| `upload.max_size_image_mb` / `max_size_video_mb` / `max_size_file_mb` | int | `0` | 上传大小上限（MB）的**回落值**。文件模块实际生效的限制 = 「系统设置 → 高级 → 参数」页的「上传限制」（`sys_config` 的 `upload.max_size_*_mb`、`upload.allowed_types`）里设了的项，页面没设的项（大小为 0 / 空，类型列表为空）回落到这里，这里也为 0 才是不限制。注意这意味着页面里填 0 不能放宽这里已设的上限。页面保存后立即在本实例生效，多实例最多晚 5 秒（短缓存）。“允许上传的文件类型”只在参数页设置（config.yaml 没有对应项），出厂参数里有一份默认白名单（图片 / mp4 / webm / pdf / doc(x) / xls(x) / zip），清空即不限制类型 | 需要部署层面的上传上限，或页面还没设置时 |
| `storage.driver` | string | `local` | `local`：保存到 `data/uploads/files`（断点续传临时文件在 `data/uploads/tmp`）；`s3`：S3 兼容存储 | 使用对象存储 |
| `storage.s3.endpoint` | string | 空 | 如 `https://s3.amazonaws.com`、`http://minio:9000`、`https://oss-cn-hangzhou.aliyuncs.com` | `driver=s3` 必填 |
| `storage.s3.bucket` / `access_key` / `secret_key` | string | 空 | 桶与凭据，`driver=s3` 必填；支持 `${ENV}`，密钥不要写进仓库 | `driver=s3` |
| `storage.s3.region` | string | 空 | 空则按 `us-east-1` | 服务商要求区域时 |

## 6. ratelimit

固定窗口限流：同一 key 在 `window` 内最多 `limit` 次，超出返回 HTTP 429 和 `Retry-After`。`limit <= 0` 表示该规则不限流；`ratelimit.enabled=false` 关闭全部规则。计数放在 `cache`：`redis` 时多实例共享，`memory` 时只在本进程内；缓存出错时放行并限频告警（fail-open）。每条规则的子键是 `limit`（int）和 `window`（duration），环境变量如 `NEXADMIN_RATELIMIT_LOGIN_LIMIT`。

| 键 | 默认 | 维度与适用接口 |
| --- | --- | --- |
| `ratelimit.enabled` | `true` | 总开关 |
| `ratelimit.login` | 20 次 / `1m` | IP + 路由；`POST /auth/login`、第三方登录回调等登录类接口 |
| `ratelimit.captcha` | 30 次 / `1m` | IP + 路由；`GET /auth/captcha` |
| `ratelimit.sms_code` | 5 次 / `1m` | IP + 路由；`POST /auth/sms-code` |
| `ratelimit.token` | 10 次 / `1m` | SSO `/oauth/token` 的失败次数（同 IP 或 IP + client），超限 429 |
| `ratelimit.setup` | 30 次 / `1m` | IP；初始化向导 `/api/v1/setup/*`（未初始化时使用进程内 memory 计数） |
| `ratelimit.upload` | 120 次 / `1m` | 登录用户；文件上传（tus 创建与追加） |
| `ratelimit.ai` | 30 次 / `1m` | 登录用户；`/ai/*`。AI 网关内部另有每用户每分钟 20 次的默认限制 |
| `ratelimit.pat_create` | 10 次 / `1h` | 登录用户；创建个人访问令牌 |
| `ratelimit.openapi_sign` | 30 次 / `1m` | IP；开放平台令牌 / 应用签名校验失败次数 |
| `ratelimit.client_error` | 30 次 / `1m` | IP；`POST /api/v1/client-errors` 前端错误上报 |
| `ratelimit.dashboard_layout` | 30 次 / `1m` | 登录用户；`/api/v1/dashboard/layout` 工作台布局读写 |
| `ratelimit.log_export` | 10 次 / `1m` | 登录用户；操作日志与登录日志导出（两个接口共用同一计数） |

## 8. 代码会读取、但 default.yaml 没有声明的键

下列键由所在模块自行读取 `config/default.yaml`、`config/config.yaml` 与环境变量（同样遵守 `NEXADMIN_` 规则），不经过 `core/config` 的校验：

| 键 | 读取处 | 作用 |
| --- | --- | --- |
| `sso.issuer` | `modules/sso` | OIDC issuer。默认 `<站点>/api/v1/oauth`；生产环境应显式配置。环境变量 `NEXADMIN_SSO_ISSUER`。其 host 也参与插件授权的域名校验 |
| `site.domain` / `site.domains` | `core/plugin` | 站点域名，仅用于插件授权文件带 `domains` 时的域名比对。都没配置时取第一次带 Host 的请求 |
| `license.allow_dev_hosts` | `core/plugin` | 为 `true` 时，授权域名校验把 `localhost`、`127.0.0.1`、`::1`、`*.localhost` 视为匹配（本机开发用） |
| `identity.allow_private_hosts` | `plugins/identity` | 默认 `false`：LDAP 地址与 CAS `serverUrl` 拒绝回环 / 私网 / 链路本地 / CGNAT / 云元数据地址（保存配置时查字面量，连接前解析全部 A/AAAA，connect 时对实际 IP 再查一次）。内网部署的目录与 CAS 本来就在私网里，必须显式设为 `true` 才能连通。环境变量 `NEXADMIN_IDENTITY_ALLOW_PRIVATE_HOSTS`；插件热挂载时只放行、不收回 |

## 9. 只能用环境变量的项

| 变量 | 作用 |
| --- | --- |
| `NEXADMIN_SECRET_KEY` | 静态加密主密钥（AES-256-GCM，32 字节，hex 或 base64）。优先于 `data/secret.key`；没设置则首次启动自动生成 `data/secret.key`（hex，权限 0600）。丢失主密钥则已加密的值无法恢复，要和数据库一起备份 |
| `NEXADMIN_MIGRATIONS_DIR` | 指定 `migrations/framework` 目录，业务迁移取它旁边的 `business`；未设置则从当前目录及上级、可执行文件所在目录及上级查找 `migrations/framework` |
| `NEXADMIN_SHUTDOWN_TOKEN` | 内部使用：`start` 用它把关停令牌交给后台进程，进程读取后立即清除。不要手工设置 |

## 10. 设置页与配置文件的关系

“系统设置”页（完整后台地址 `/admin/system/settings`）共十个 UI 分区：`site`、`security`、`cache`、`storage`、`ai`、`sms`、`auth`、`notify`、`language`、`params`。前八个由 settings API / `sys_setting` 管理；语言读写 `/languages` / `sys_language`，参数读写 `/configs` / `sys_config`，不把后两者传给 `/settings/:section`。这些是平台全局配置，仅交由平台超管管理；接口权限边界与导航分组见[功能清单](功能与权限清单.md)。运行优先级与限制：

- `ai`：设置页分区优先，没保存过时回落到 `ai.*`。
- 登录安全（连续失败次数、锁定分钟）：设置页 `security` 分区 → 系统参数 `login.max_retry` / `login.lock_minutes` → 默认 5 次 / 15 分钟。
- `storage`：文件存储以 `config/config.yaml` 为准。设置页保存 `storage` 分区会被拒绝并返回 400（单测 `TestSaveStorageSectionRejected` 的注释写明“而不是保存成功却不生效”）。
- 其余分区（`cache`、`sms`、`auth`、`notify`、`site`）与 YAML 对应项的运行时关系：未逐项核对。部署层面的依据以 YAML 为准。
