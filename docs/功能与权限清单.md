- `assistant` 路由要求 `assistant:use`，主项目与独立包后端均为 1.1.0，包含个人命名会话 CRUD，每租户每用户最多 30 个；查询显式带 `tenant_id` 和 `user_id`。清单的迁移目标为平台库，不能按业务表迁入租户库。Go 模型和三引擎 SQL 的表名统一为 `plg_assistant_conversation`，Go 实体 ID 为 `string`，由 `newID()` 使用 `crypto/rand` 生成 16 字节并编码为 32 位小写十六进制字符串，SQL 主键为 `CHAR(32)`；入口 `validConversationID` 校验长度及 `0–9`、`a–f` 字符集，不使用雪花 ID 或 `pkg/idgen`。PostgreSQL 索引指向该表。开发期直接修正了 001 迁移。sqlmock 单测覆盖创建、列表、读取与租户/用户隔离；未在真实数据库执行 SQL，不能据此认定表已建立或持久化已验收。
- 停用 `user` 模块会同时失去登录提供者和初始化向导的建超管 / 判定入口（`core` 从模块里收集这些角色），不要停用；停用其他模块的影响由模块之间“表不存在退化为空”的约定兜底，未逐个实测。
- 数据范围裁剪实际用在：用户列表与读写、部门（写操作；读取仅 `scene=manage`）、公告（管理端按创建者裁剪，发布对象另有限制）、操作日志与登录日志（`core/datascope`、`modules/system/user/scope.go`）。
- 审计与后台任务的操作人：`core/auth` 的 `ContextWithUser` / `UserFromContext` 只用于归属记录（不是 Claims，过不了任何权限校验）；`core/job` 执行处理器时以提交者和 `job:<type>` 放入 context，`audit` 插件的操作人解析顺序为 `WithOperator` → `ClaimsFromContext` → `UserFromContext` → 系统。

## 2. 登录与认证

### 2.1 登录方式

登录页按配置显示，没配置的不显示、不报错（`GET /api/v1/auth/methods` 返回 `methods`、`providers`、`forgotEnabled`）。三种方式登录成功后发同一套 JWT 双 token。

| 方式 | 启用条件 | 规则（来自代码） |
| --- | --- | --- |
| 账号密码 | `auth.methods` 含 `password`（默认） | 同一用户名或同一 IP 连续失败 ≥3 次后要求图形验证码（4 位数字，60 秒有效，一次性）；连续密码错误达到上限锁定账号，默认 5 次 / 15 分钟，可在设置页 `security` 分区或系统参数 `login.max_retry`、`login.lock_minutes` 调整；用户不存在时也做一次 bcrypt 比较，对外统一提示“用户名或密码错误”，真实原因只进日志；锁定状态按“存在 / 不存在的用户名一视同仁” |
| 手机号 | `auth.methods` 含 `phone` 且 `sms.provider` 非空，否则自动隐藏 | 手机号必须已绑定账号；验证码 5 分钟有效，同一手机号 60 秒只能发一次、每天最多 10 条，同一 IP 每小时最多 10 条，连续输错 5 次作废 |
| 第三方快捷登录 | `auth.providers.<name>` 配置完整 | OAuth2 授权码流程：企业微信、钉钉、飞书、Google（OIDC，授权码 + PKCE）、GitHub、通用 OIDC（Keycloak、Casdoor 等）。`state` 一次性、回调地址白名单精确匹配；首次登录按 `match_by` 匹配已有账号，匹配不上提示“绑定已有账号”，`auto_create: true` 才自动建号；邮箱只认已验证邮箱；个人中心可绑定 / 解绑 |

第三方登录的配置键见《配置参考》第 3 节。前端回调页是 `/admin/login/oauth/<provider>`，`redirect_uris` 必须是它的完整 URL。Google / GitHub 需要服务器能访问外网，受限网络配 `auth.proxy`。

### 2.2 令牌与会话

- access token（默认 30 分钟）和 refresh token（默认 168 小时），HS256 签名；刷新时旧 refresh 立即作废；登出吊销当前 access 及其配对的 refresh；吊销记录存缓存，缓存不可用时拒绝放行。
- 可选 `auth.single_session: true`：同一租户、同一用户仅保留最后一次登录；旧 access/refresh 被拒绝，刷新使用缓存原子比较替换，避免旧会话覆盖新登录。默认关闭，多实例须共享 Redis 并保持配置一致。
- 租户过期 / 停用的用户不能登录、不能刷新令牌、已登录的请求也被拒绝（第 6 节）。
- 忘记密码（`POST /auth/forgot/send-code`、`/auth/forgot/reset`）：邮件渠道（设置页“通知渠道”SMTP）配置后才可用；验证码 10 分钟有效，冷却 60 秒，最多尝试 5 次，另有按 IP 与按账号的小时级限流。
- 在线会话是被动登记的：已登录用户访问接口时按“用户 + IP + UA”记入缓存，强制下线会吊销该会话最近一次见到的令牌。

## 3. 开放平台

模块 `openapi`，菜单“系统管理 → 开放平台”，权限 `openapi:list`（读）/ `openapi:edit`（写）。

- 个人访问令牌（PAT）：登录用户在个人中心自助创建，明文形如 `nxp_<32 位随机>` 只显示一次，库里只存 sha256；用 `Authorization: Bearer nxp_...` 调用，等同令牌所有者；令牌不能调用令牌管理接口本身；创建按用户限流（`ratelimit.pat_create`）。
- 应用签名调用：开放应用（服务账号）绑定角色集合，可配 IP 白名单，调用时带请求头 `X-App-Key`、`X-Timestamp`、`X-Nonce`、`X-Signature`。签名 = `hex(HMAC-SHA256(appSecret, METHOD\npath\n规范化query\nsha256hex(body)\ntimestamp\nnonce))`，其中 `path` 是请求完整的 URL 路径（含 `/api/v1`，取 `EscapedPath`），`timestamp` 为 Unix 秒，时间窗 ±5 分钟，`nonce` 一次性（重放会被拒绝并提示 `nonce already used`，重放检测依赖缓存），参与签名的请求体上限 10MB；query 按 key 排序、同 key 的 value 也排序，key / value 都做 `url.QueryEscape` 后用 `&` 连接。应用密钥可重置，库里存 `core/secret` 加密后的密文。校验失败按 IP 限流（`ratelimit.openapi_sign`）。
- 事件目录：`GET /openapi/events`。当前共 10 个事件：`user.created` `user.updated` `user.deleted`、`dept.created` `dept.updated` `dept.deleted`、`role.created` `role.updated` `role.deleted`、`notice.published`。事件载荷只放 id、必要字段和租户 id，不带密码哈希、密钥。进程内事件总线队列容量 1024，队列满则丢弃并告警，不阻塞业务请求。
- Webhook：配置 URL（做 SSRF 防护）和订阅事件，投递带请求头 `X-Nex-Event`、`X-Nex-Delivery`、`X-Nex-Timestamp`、`X-Nex-Signature`（`hex(HMAC-SHA256(secret, timestamp + "." + body))`），单次超时 5 秒，最多尝试 5 次（失败后依次等待 1 分钟、5 分钟、30 分钟、2 小时），投递记录保留 30 天，可手动重试和测试；Webhook 密钥形如 `whsec_...` 可重置，库里加密存放。
- 接口文档：`GET /openapi.json`（OpenAPI 3.0.3，原始 JSON，不套统一响应体）和 `GET /openapi/routes`（运行时路由清单），权限 `openapi:list`；停用的模块不出现在文档里。
- MCP 入口：`POST /mcp`（权限 `mcp:list`），支持 JSON-RPC `initialize`、`ping`、`tools/list`、`tools/call` 和通知；协议版本 `2025-03-26`。GET 工具直接调用，显式注册的写工具走服务端确认流程（当前消息模块注册 `message_mark_read`），不会开放任意写路由或任意 URL。实际调用重新经过原路由登录、权限与租户检查，应用签名不能作为用户 Bearer 凭据复用。`GET /mcp/tools` 保留目录。
- MCP 会话：初始化返回 `Mcp-Session-Id`，后续携带该头；`DELETE /mcp` 删除会话。元数据与每会话最多 4 个并发请求槽位存在配置缓存，多实例须共享 Redis / Valkey；固定有效期取 15 分钟与初始化凭据剩余寿命的较短者，不随活动或刷新延长，且绑定具体身份与凭据。每实例最多跟踪 1024 会话、64 并发请求；请求最长 30 秒，缓存异常拒绝并取消相关请求上下文。会话 ID 不能替代认证。
- MCP 写确认：先返回 `confirmationId` 和浏览器确认地址；用户通过浏览器 `/admin/mcp/confirmations/:id` 查看，并以会话 JWT 和本地密码调用 `POST /mcp/confirmations/:id/approve`，确认有效期 5 分钟。PAT / 应用签名不能用于浏览器批准；批准后以相同工具和 `confirmationId` 再调用，服务端重新核验并原子消费，客户端 `confirmed` 不能绕过。支持 JSON 或最终单条 SSE 响应封装；不支持批量请求、GET 长连接、事件重放、进度流或转发上游工具 SSE。以上为静态代码核对，真实 Redis 多实例与浏览器链路未验收。

## 4. 付费插件机制（简述）

插件以源码包交付：安装 = 拷文件 + 重新编译；`edition: free` 不校验授权，`edition: pro` 需要离线签名的授权文件（`data/licenses/<id>.lic`，ed25519 签名，载荷含插件、客户、签发 / 到期时间，可选域名）。

- 命令：`nexadmin plugin list | install | remove | keygen | sign | revoke`（用法见 `nexadmin` 的 usage；`sign` / `revoke` 是发行方用的签发与吊销）。
- 校验：启动时逐个校验，有效才挂载路由和菜单；缺失 / 过期 / 被篡改不挂载，插件管理页显示原因；导入授权后热挂载，不用重启。运行中每小时复查一次，到期的插件路由返回 403；到期前 30 天在 `GET /plugins` 里带 `expiresSoon`；授权带 `domains` 时校验当前服务域名（精确或 `*.example.com`，来源见《配置参考》第 8 节）；`requires_nexadmin` 在加载时按框架版本校验；发行方可另发签名的吊销清单 `config/license-revoked.json`，序列号命中的授权状态为 `revoked`（路由返回 403，文件变化后无需重启；辅助手段，买家可删除清单）。
- 约定与开发流程见《plugin-development.md》。该文档末尾“已知限制”一节已与代码行为一致（域名校验、版本范围校验、到期自动下线均已实现）。

## 5. 角色与数据范围

### 5.1 RBAC

用户 → 角色 → 菜单 / 按钮权限，权限码命名 `模块:动作`；超管（`*`）短路放行；权限每次请求从登录提供者读取最新值，不信令牌里的快照。新增菜单 / 权限点只有超管默认可见，其他角色要到“角色管理”分配。出厂角色：`admin`（超级管理员，内置，不可删除 / 停用 / 改编码，不可被分配）、`operator`、`auditor`、`editor`（默认停用）、`guest`、`secadmin`（演示“不可被分配”）。后五个是演示角色，菜单授权默认留空。

### 5.2 数据范围

角色的 `data_scope` 字段，取值：

| 取值 | 含义 |
| --- | --- |
| `all` | 全部 |
| `deptAndChild` | 本部门及以下（依赖 `sys_dept.path` 物化路径；取不到时退化为本部门） |
| `dept` | 本部门 |
| `self` | 仅本人 |
| `custom` | 自定义部门集合（`sys_role_dept`） |

用户有多个角色时取并集：任一角色是 `all` 即全部；预设范围取最宽的一档；自定义部门与预设展开的部门合并成一个集合。超管恒为全部。操作者自己永远在范围内；“本部门 / 本部门及以下”的用户没有所属部门时视为仅本人。范围用在用户、部门、公告、操作日志、登录日志的读写裁剪（部门的读取裁剪仅在部门管理页带 `scene=manage` 时生效；非超管且范围非“全部”的操作者发公告时，发布对象也受该范围限制）。

### 5.3 角色可分配的三道校验

非超管把角色分配给别人（新增 / 编辑用户、导入用户、角色选项）时，三道校验按顺序独立判断，报告第一个不满足的（`core/roleassign`）：

1. 角色可分配：`assignable=true`，且不是内置超管角色，且权限里不含 `*`。不满足提示“该角色不允许被下级管理员分配”。
2. 权限不超出：角色的权限集合必须是操作者当前权限集合（多个角色取并集）的子集。不满足提示“所选角色的权限超出了你自己的权限范围，不能分配”。
3. 数据范围不更宽：要分配的角色范围不能比操作者的范围更宽。不满足提示“所选角色的数据范围比你的数据范围更宽，不能分配”。判定表（行 = 角色范围，列 = 操作者范围；`全部` 的操作者一律允许）：

| 角色 \ 操作者 | 全部 | 本部门及以下 | 本部门 | 仅本人 | 自定义（集合 S） |
| --- | --- | --- | --- | --- | --- |
| 全部 | 允许 | 拒绝 | 拒绝 | 拒绝 | 拒绝 |
| 本部门及以下 | 允许 | 允许 | 拒绝 | 拒绝 | S 对下级封闭（每个部门的整棵子树都在 S 内）才允许 |
| 本部门 | 允许 | 允许 | 允许 | 拒绝 | 允许 |
| 仅本人 | 允许 | 允许 | 允许 | 允许 | 允许 |
| 自定义（集合 R） | 允许 | R ⊆ 操作者可见部门 | R ⊆ {本部门} | 仅 R 为空才允许 | R ⊆ S |

操作者的权限与数据范围实时从库里读取。公开包 `nexadmin/core/roleassign`、`nexadmin/core/datascope` 可供业务模块直接使用。

## 6. 租户额度与到期强制

租户由“租户管理”维护，字段含状态（`active` / `suspended` / `expired`）、到期时间（空为永不过期）、套餐、域名，以及可覆盖套餐的用户数 / 角色数 / 存储（MB）额度；额度为 0 表示不限。租户自己的额度优先，其次取套餐。出厂会写入 12 个演示套餐和若干演示租户。

到期与停用：

- 状态判定：`suspended` / `expired` 直接拒绝；有到期时间且已过期时，若在宽限期内放行（`StateGrace`），超出宽限期拒绝。宽限天数取系统参数 `tenant.grace_days`（默认 0），到期提醒天数取 `tenant.expire_warn_days`（默认 15，0 为不提醒）。
- 强制点：登录、刷新令牌、第三方登录签发令牌前都校验；已登录的非超管请求（含个人访问令牌和应用签名调用）在每次请求的租户中间件里校验，登出放行，让前端能清理会话；被拒绝返回 HTTP 403，`reason: TENANT_EXPIRED`。平台超管和默认租户（不受管）不受影响。
- 到期提醒：`GET /auth/me` 在到期前 `expire_warn_days` 天内（含宽限期）带 `tenantExpireSoon`（到期时间与剩余天数）。
- 续期 / 启停：`PUT /tenants/:id/renew`、`PUT /tenants/:id/status`（权限 `tenant:update`）；租户信息有 30 秒进程内缓存兜底，修改后会通过 `core/cluster` 广播失效事件，其他实例通常立即生效，广播丢失时最多延迟 30 秒（多实例细节见《部署与运维指南》第 10 节）。

额度强制（超出返回 HTTP 403，对应 `reason`）：

| 额度 | 强制位置 | reason |
| --- | --- | --- |
| 用户数 | 新增用户、导入用户、第三方登录自动建号（同一事务内先锁租户行再统计，并发不超额） | `TENANT_QUOTA_USERS`（“用户数已达套餐上限（N 个），无法继续新增”） |
| 角色数 | 新增角色（同上，先锁租户行再统计） | `TENANT_QUOTA_ROLES`（“角色数已达套餐上限（N 个），无法继续新增”） |
| 存储 | tus 创建会话时按声明长度原子预占，将实际用量与进行中预占合并检查；完成、取消等路径释放预占，过期预占按租约清理（`modules/file/usage.go`） | `TENANT_QUOTA_STORAGE`；受限上传要求缓存实现 `cache.Lease`，不支持则拒绝；多实例须使用共享缓存，真实 Redis 并发仍待验收 |
| AI 开关 | 租户可被单独关闭 AI（`sys_tenant.ai_enabled`）；AI 网关在 `/ai/*` 调用时检查，平台超管与默认租户不受限 | `TENANT_AI_DISABLED` |
| AI 每日调用次数 | 套餐 `ai_daily_quota`（0 为不限），租户可覆盖（空为沿用套餐，0 为不限）；`filter`、`translate`、`write` 共用同一份次数，平台超管与默认租户不受限 | `TENANT_QUOTA_AI` |

套餐还可以限定菜单范围：用户的有效权限会与套餐菜单对应的权限取交集（套餐菜单为空则不限制）。跳过租户隔离的平台级操作（超管端）不受额度限制。
