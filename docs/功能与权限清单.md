# NexAdmin 功能与权限清单

本文列出内置模块、权限码与接口、登录方式、开放平台、插件机制、角色与数据范围、租户额度与到期、关键词搜索的大小写折算。数据来源：

- 路由与权限码：以各模块 `module.go` / 插件路由为准，可用框架仓库的 `scripts/contract_check` 解析核对。附录是常用接口对照，不是固定的路由总数；新增接口与插件以各自源码、交付清单及运行时 OpenAPI 为准。动态插件路径由管理器按已注册插件装配。
- 菜单：`modules/system/menu/seed.go`（出厂菜单，业务键 = 权限码；菜单名取自前端 zh-CN 语言包）。
- 列表页批量操作约定：批量删除统一为 `DELETE <集合路径>?ids=1,2,3`，由 `core/response.ParseIDs` 校验——任一项非法或整体为空一律 400，绝不退化成「不带 ids 即全量删」；一次点名超过 `MaxBatchIDs`（500，与文件模块自知的阈值一致）也 400，因为几千个占位符会让一条 `IN (...)` 先变成 500。复用该行已有的删除权限码，不新增权限点；返回 `{"deleted": 实删条数, "blocked": 点名但未删条数}`，仍被引用、超出数据范围或不存在的行计入 blocked 而不是让整批失败。前端统一走 `DataTable` / `TreeTable` 的 `selection` + `batchActions`（树形勾父带子，与后端级联删除同口径），CSV 导出统一走 `web/src/framework/components/export`。
- 租户隔离：看模型嵌入的基座——`TenantModel`（带 `tenant_id`，查询自动追加租户条件）为“是”，`PlatformModel` 为“否（平台级）”。表里写“否（平台级）”的还有第二层含义，见第 1 节开头：**它们的写入口除权限点外统一挂 `core.RequirePlatform()`，只认平台级调用方**；读与列表照常。
- 接口前缀均为 `/api/v1`，只有 `/healthz` 和 `/metrics` 在根路径。常用“权限码 ↔ 接口”对照见附录。

本文描述接口与使用边界，不构成环境验收报告。真实数据库、Redis 多实例、LDAP/AD/CAS、浏览器与部署链路仍须单独验收。省市区数据随包发布大陆快照（31 省级 / 333 地级 / 2847 县级，来源、日期与许可见 `core/region/data/manifest.json`：来源 `mumuy/data_location`，MIT 为提供者声明，并附源/产物 SHA-256；这份记录是提供者的说法，本文未独立核实，故不证明各省市县数据完整或现行有效，也不要当官方授权数据交付），港澳台另存一份补全数据（`regions_sar.json`：港澳带下辖区/堂区，台湾省只到省级），生效的一律是 34 个省级；管理员可在「系统设置 → 省市区数据」从 HTTPS 数据源重新同步（同步是 `sys_region_snapshot` 的全局行，非超管要按第 1 节开头那条平台级判据），数据源缺港澳台时按补全数据填上、源里带了就以源为准。同步只替换省市区列表，不改动业务表里已存的区划代码。首次使用见[快速开始](quickstart.md)。

## 1. 内置模块清单

“模块名”是 `config` 里 `disabled_modules` 要写的名字（模块的 `Name()`）。动作缩写沿用本行模块前缀，例如 user 行的 `create` 指 `user:create`。下表后台路径相对 `/admin`，如 `/system/settings` 的完整入口为 `/admin/system/settings`。

**平台全局管理只交给平台级调用方**，不向普通租户角色下放设置、语言、全局菜单/字典、插件安装/授权、备份、租户与套餐等管理权限。这里的“平台级”不只是数据归属，它已经焊进路由，判据是 `core.IsPlatformCaller`（`core/router.go:51`）：**超管，或请求落在默认租户**（单源在 `tenant.IsPlatformCallerID`，随会话以 `auth.User.Platform` 下发给前端）。`core.RequirePlatform()`（`core/router.go:63`）现在挂在 **55 条写路由**上，每条除原有权限点外再过这道闸：工单的快捷回复 / SLA 与命名策略 / 分组与成员 / 自动化规则 / 自定义字段 / 插件设置（`plugins/ticket/handler.go:605-653`，17 条）、代码生成器的 `POST /plugins/codegen/install` 与保存配置（`plugins/codegen/plugin.go:37-41`，4 条）、参数与设置分区（`modules/system/config/module.go:72-86`，8 条）、参数字典的类型与字典项**含两处排序**（`modules/system/dict/module.go:27-44`，10 条）、菜单**含拖拽排序与移动**（`modules/system/menu/module.go:39-45`，6 条）、语言清单整表保存（`modules/system/language/module.go:26`，1 条）、省市区 `preview|import|sync|reset|rollback`（`modules/region/module.go:100-106`，5 条）、ldap / maps / media 三个凭据页（4 条）。逐条对照见附录里带“另要求平台级”的那几行。

**租户管理员要预期的是：即使持有 `ticket:edit`、`dict:update`、`menu:update`、`settings:update` 这些权限点，保存仍然回 403**，错误 key 是 `error.platform_only`（文案在 `core/i18n/locales/{zh-CN,en-US}.yaml`，整句直接说明「该项是平台级共享配置、所有租户共用同一行，只有平台管理员能修改」，不是让人回头翻自己的角色）；写权限已收口的前端把写按钮置灰并显示一行 `<PlatformNotice />` 说明，而不是让入口蒸发。原因一句话：**这些表没有 `tenant_id`，租户的一次保存改写的就是所有租户共用的那一行**——权限点回答“能不能用这个模块”，回答不了“能不能改别人也在用的那一行”。所以“下放给租户自助”不是待办，而是一个需要先做租户化改造的决定（三引擎迁移补 `tenant_id` + 唯一键改形，改造前这一档只归平台；见本节末尾的总不变式与 `scripts/contract_check`）。单租户部署里人人都落在默认租户=平台调用方，这条闸不改任何行为，只在多租户下生效。另有两张表用更强闸：`sys_backup` / `sys_backup_setting` 走 `superOnly()`、`sys_tenant` / `sys_tenant_pkg` 走分组级 `RequireSuper`，表中“平台级”一格不等于这两条闸的都有 `RequirePlatform`。

## 2. 登录与认证

### 2.1 登录方式

登录页按配置显示，没配置的不显示、不报错（`GET /api/v1/auth/methods` 返回 `methods`、`providers`、`forgotEnabled`）。三种方式登录成功后发同一套 JWT 双 token。

| 方式 | 启用条件 | 规则（来自代码） |
| --- | --- | --- |
| 账号密码 | `auth.methods` 含 `password`（默认） | 系统参数 `login.captcha_enabled` 出厂为 false（无感优先，对标主流商业验证码）：正常登录不出验证码，同用户名或同 IP 连续失败 ≥3 次后才按自适应策略强制（滑块档），**连错达到 6 次升级为点选档**（连错含密码失败，滑块拖错也计入 IP 维度升级计数——磨滑块的自动化同样会升级，且升级即时生效：拖错把 IP 计数推过硬阈值时，交卷失败响应当场带 `CAPTCHA_REQUIRED_HARD`，前端立即切点选，不必等下一次密码失败；而锁定只数密码失败且按用户名，真人手滑不会被锁号；`GET /auth/click` 出题、`POST /auth/click/verify` 交卷：384×150 主图混入干扰字 + 候选字条按顺序点选 2~3 个字，点位只存服务端，逐点容差比对，单个挑战最多校验 5 次）。验证码默认形态是滑块拼图（`GET /auth/slider` 出题、`POST /auth/slider/verify` 交卷）：384×150 背景挖一个孔（孔位 X 有合法区间约束重试；与登录表单通栏对齐，窄屏前端等比缩放），把滑块图拖到位后签发一次性 token，写进与图形验证码同一个缓存键，所以登录、短信、注册三条链路仍走同一道 `VerifyCaptcha` 消费闸（绑定 IP、校验一次即作废；签发的 token 带形态标记——滑块 `s|`、点选 `c|`，图形码文本无标记）；**登录硬档在服务端只接受点选 token（`VerifyCaptchaHard`）**，滑块 token 与图形码文本都过不了，所以直接调 `/auth/slider` 换 token 的脚本被挡在服务端，而不只是前端切换了形态；孔位横坐标不从前端可见的 key 派生（手绘回退版用 `crypto/rand` 抽取），另外还看轨迹（≥6 个点、时长 150ms–15s、推进 ≥40px、落点 ±6px、多点轨迹的速度离散度与瞬移上限），单个挑战最多校验 3 次（拖错即换发新挑战）。两种形态的底图素材共 21 张，且每次出图叠加随机色调扰动（背景与抠块同一运算），预标记图库无法定位孔位。滑块交互由 rc-slider-captcha（MIT）内嵌面板承担：拼图面板与拖轨都在表单流内，通过后收起成一行徽标（「重新验证」换新挑战）；三种形态均带右上角刷新按钮。前端只接后端契约；形态由服务端按风险指派、用户不可降级（点选档切不走），界面上唯一的出口是「改用图形验证码」（可输入、有语音，无障碍兜底），再「改用」回服务端指派的形态；**但硬档在服务端只认点选 token，图形码文本会被拒**（计数 15 分钟固定窗口后自愈）——这是用这段可用性换掉滑块旁路的取舍。运营指标经 `/metrics` 暴露：`nexadmin_auth_captcha_issued_total` / `verify_pass_total` / `verify_fail_total`（按 image/slider/click 分型）与 `escalation_total`（按 slider/click 分级）。一键可换成图形数字码（5 位数字，224×72 字形渲染带随机缩放/倾斜/波扭曲，60 秒有效，一次性；`GET /auth/captcha/:key/audio` 可把同一张验证码读成音频，只读不消费，语音随界面语言选 zh / en）。连续密码错误达到上限锁定账号；回落值为 5 次 / 15 分钟，出厂系统参数的锁定时长为 30 分钟，可在设置页 `security` 分区或系统参数 `login.max_retry`、`login.lock_minutes` 调整；登录会话默认闲置 2 小时退出、最长 12 小时（设置页 `security` 分区的 `idleMinutes` / `maxHours`，`0` = 不限制，改完即时生效）；用户不存在时也做一次 bcrypt 比较，对外统一提示“用户名或密码错误”，真实原因只进日志；锁定状态按“存在 / 不存在的用户名一视同仁”，并落库到 `sys_login_lock`（按租户 + 用户名，过期行最多每小时清理一次、下次建锁时触发）：缓存只是快路径，进程重启或换实例后仍拒绝被锁账号的正确密码 |
| 手机号 | `auth.methods` 含 `phone` 且 `sms.provider` 非空，否则自动隐藏 | 手机号必须已绑定账号；验证码 5 分钟有效，同一手机号 60 秒只能发一次、每天最多 10 条，同一 IP 每小时最多 10 条，连续输错 5 次作废 |
| 第三方快捷登录 | `auth.providers.<name>` 配置完整 | OAuth2 授权码流程：企业微信、钉钉、飞书、Google（OIDC，授权码 + PKCE）、GitHub、通用 OIDC（Keycloak、Casdoor 等）。`state` 一次性、回调地址白名单精确匹配；首次登录按 `match_by` 匹配已有账号，匹配不上提示“绑定已有账号”，`auto_create: true` 才自动建号；邮箱只认已验证邮箱；个人中心可绑定 / 解绑 |

第三方登录的配置键见《配置参考》第 3 节。前端回调页是 `/admin/login/oauth/<provider>`，`redirect_uris` 必须是它的完整 URL。Google / GitHub 需要服务器能访问外网，受限网络配 `auth.proxy`。

- **登录滑块的交互交给 rc-slider-captcha（MIT），三处坑已钉死（2026-11-06）**：① 组件只在挂载时 `autoRequest` 为真、或显式 `actionRef.refresh()` 才发 `request`，两者都不给就是「滑轨在、拼图永不加载」——连错 3 次密码强制验证码后等于锁死登录；现在靠挑战 `key` 变化重挂自动取图。② rc 把把手行程按 `ratio = (bgW - puzzleW) / (bgW - buttonW - 2)`（280/63/40 → 217/238）换算成拼图行程，「把手位移 = 图片像素」的假设不成立（实测鼠标 184px、拼图 167.75px）；前端尺寸全部从真实 DOM 量。交卷上报也统一到拼图行程口径：rc 的 trail 记的是绝对 clientX，原样发会让后端「推进量 ≥40px」量成页面横坐标跨度，现按首点平移、按落点缩放，与 `x` 同坐标系。时间轴随后从「按总时长线性铺开」换成 `pointerdown/move` 的真采样（`sliderTrail.ts`：样本 ≥`TRAIL_MIN_SAMPLES`=6 才用，不足才退回线性铺开）——线性铺开的最大间隔只有 `总时长/点数`，装不出真人中途的停顿，所以时间轴必须来自真实 `pointerdown/move` 采样（真人在中途停顿后仍要能通过）；顺带清掉迁移遗留：只传不用的 `actionRef`、无人使用的 `IMG_W`、过时的 `imgH` 兜底 120 → 出厂口径 110。③ `puzzleSize` 的 `height` 是它 README 里写明的字段，不传就按文档默认「高度为背景图高度」把 63×63 的滑块图拉成 63×110（`object-fit` 默认 fill），滑块块看着是一团压扁的白框、与孔位形状永远接不上；横向行程不受影响，所以照样拖得动、判得过，错的只有画面——实测渲染盒 63×110 对原图 63×63。现在按响应里的 `pieceHeight` 显式传高度（`pieceWidth` 的兜底也从库默认宽 68 换成出厂口径 63）。键盘路径按产品决策已移除，无障碍兜底是「改用图形验证码」（可输入、有语音）。归属留一行：这条泳道的前半段（rc 迁移与 e2e 改写）在 2026-11-06 被并发会话卷进了 `27a9804`、`f82ae40`、`e1adb60`、`68515d9`、`03d403b` 五个混合提交，后半段（坐标系归一化与取证闸）是 `70953b3`，本节这两条文档记录是 `f927fa9` 及其后；已推送的历史不做改写，所以要查这一段，按这几个号一起看，别只看一条。
- **真后端整链的复跑配方（本轮实测通过）**：`cd web && npm run build` → `go build -tags embedweb -o <临时目录>/nexadmin-server`（单进程同源，避开 vite dev + go run 双进程的假红）→ `nexadmin-server init --config <一次性参数>`：库用一次性名字、`NEXADMIN_MIGRATIONS_DIR` 指到 `migrations/framework`、CWD 放仓库外，免得写脏 `config/config.yaml` 与 `data/` → `NEXADMIN_SERVER_PORT=<空闲端口>` 起服务 → 浏览器侧从真 PNG 背景按 52×52 最暗窗口反查孔位、按同一 ratio 换算拖动。实测：`POST /auth/slider/verify` 回 `code:0` 并签发 token，上报轨迹 `{first:0, max:106, last:106, n:15}`（落点 106，容差 ±6），随后 `POST /auth/login` 200 且离开 `/login`，即滑块 token 真被登录那道 `VerifyCaptcha` 消费。这条冒烟要一次性库 + 本地端口，不进 CI，所以没留用例文件（留了就是没有消费者的死件）。

### 2.2 令牌与会话

- access token（默认 30 分钟）和 refresh token（默认 168 小时），HS256 签名；刷新时旧 refresh 立即作废；登出吊销当前 access 及其配对的 refresh；吊销记录存缓存，缓存不可用时拒绝放行。
- 可选 `auth.single_session: true`：同一租户、同一用户仅保留最后一次登录；旧 access/refresh 被拒绝，刷新使用缓存原子比较替换，避免旧会话覆盖新登录。默认关闭，多实例须共享 Redis 并保持配置一致。
- 租户过期 / 停用的用户不能登录、不能刷新令牌、已登录的请求也被拒绝（第 6 节）。
- 忘记密码（`POST /auth/forgot/send-code`、`/auth/forgot/reset`）：按可用的邮件 / 短信渠道及账号绑定信息提供找回；验证码 10 分钟有效，冷却 60 秒，最多尝试 5 次，另有按 IP 与按账号的小时级限流。邮箱或手机号在启用账号中不唯一时拒绝找回且不暴露账号是否存在，由管理员重置。
- 在线会话是被动登记的：已登录用户访问接口时按“用户 + IP + UA”记入缓存，强制下线会吊销该会话最近一次见到的令牌。

### 2.3 SAML 单点登录（手工复跑）

仓库里没有真 IdP 可用，下面这条链路只能人工复跑；复跑结果与未覆盖项要写进提交说明。

**已执行的部分（2026-11-09）**：用一次性实例跑过 MySQL 8.0.12（端口 3310）与 PostgreSQL 18.6（端口 55432），各从 `001_init` 顺序执行到 `008_sp_metadata_sign`，并执行角色对账 SQL（补授 2 条 / 收回 1 条 / 共享角色保留 / 内置角色不被授予），两边结果一致；`mariadb/` 目录与 `mysql/` 逐字节相同，由 MySQL 实跑覆盖，未在 MariaDB 上单独启动。同日又用一次性 MySQL 实例 + 独立服务进程跑了协议整链：建源 → 用 IdP 私钥签名的断言直接 POST ACS → 自动建号并授予映射角色 → 换组后角色被替换 → 带 SessionIndex 的 SLO 只吊销对应会话、不带索引全量吊销 → 打开签名元数据后用 SP 证书验签通过 → 导入自有证书 → 停用后 ACS 返回 HTML 错误页，10 步全过。随后又用 crewjam `samlidp` 起了本地真 IdP（带登录表单）跑通浏览器链路：SP 发起 → 302 到 IdP `/sso` → 登录表单提交 `alice/alice123` → IdP 用 assertion POST 回 ACS → 服务端 302 到深链 `/system/user?samlCode=…` → 兑换令牌后 `roles=[ops-role]`；把 IdP 侧组改成 `dev` 再走一遍，角色换成 `ops-admin` 且 `ops-role` 被收回；两条登录日志 `login_type=saml`。至此协议与服务端整链都有实测，只剩商业 IdP 的界面/配置差异。

1. **起服务**：用一次性库（`NEXADMIN_DATABASE_NAME=<新库>`）起服务；启动即执行 `plugins/saml/migrations` 的 005/007/008，先跑 `migrate --dry-run` 核对待执行清单。
2. **配源**：粘贴测试 IdP 的 EntityDescriptor（自签证书即可），启用后打开「登录时同步角色」并配一条组→角色映射。
3. **首次登录**：走一次 IdP 发起或 SP 发起登录。日志应出现 `saml role sync finished`（`desired/added` 与映射一致）；`sys_user_role` 有对应行，`plg_saml_role_grant` 有 (user, source, role) 记账。
4. **改组**：在 IdP 侧把用户换到另一个映射组后重新登录。日志的 `added/removed` 只能涉及本来源记过的角色；手工分配与其它来源授予的角色必须仍在。
5. **登出**：IdP 分别发一次带 SessionIndex 和不带 SessionIndex 的 SLO。带索引只吊销对应会话，不带索引按 NameID 全量吊销；重复登出不报错。
6. **元数据**：开「签名 SP 元数据」后下载 `?download=1` 的元数据并用 SP 证书验签；配置「元数据签名证书」后，保存未签名元数据必须被拒。
7. **证书**：「导入证书与私钥」换一对自签证书后能重新登录；旧证书 7 天内仍参与解密（prev），到期后不再出现在元数据里。
8. **失败页**：停用源后从 IdP 再跳一次 ACS，浏览器应看到错误页（原因 + 返回登录）；`Accept: application/json` 的请求仍回 JSON。

## 3. 开放平台

模块 `openapi`，菜单“系统管理 → 开放平台”，权限 `openapi:list`（读）/ `openapi:edit`（写）。

- 个人访问令牌（PAT）：登录用户在个人中心自助创建，明文形如 `nxp_<32 位随机>` 只显示一次，库里只存 sha256；用 `Authorization: Bearer nxp_...` 调用，等同令牌所有者；令牌不能调用令牌管理接口本身；创建按用户限流（`ratelimit.pat_create`）。
- 应用签名调用：开放应用（服务账号）绑定角色集合，可配 IP 白名单，调用时带请求头 `X-App-Key`、`X-Timestamp`、`X-Nonce`、`X-Signature`。签名 = `hex(HMAC-SHA256(appSecret, METHOD\npath\n规范化query\nsha256hex(body)\ntimestamp\nnonce))`，其中 `path` 是请求完整的 URL 路径（含 `/api/v1`，取 `EscapedPath`），`timestamp` 为 Unix 秒，时间窗 ±5 分钟，`nonce` 一次性（重放会被拒绝并提示 `nonce already used`，重放检测依赖缓存），参与签名的请求体上限 10MB；query 按 key 排序、同 key 的 value 也排序，key / value 都做 `url.QueryEscape` 后用 `&` 连接。应用密钥可重置，库里存 `core/secret` 加密后的密文。校验失败按 IP 限流（`ratelimit.openapi_sign`）。
- 事件目录：`GET /openapi/events`。当前共 10 个事件：`user.created` `user.updated` `user.deleted`、`dept.created` `dept.updated` `dept.deleted`、`role.created` `role.updated` `role.deleted`、`notice.published`。事件载荷只放 id、必要字段和租户 id，不带密码哈希、密钥。进程内事件总线队列容量 1024，队列满则丢弃并告警，不阻塞业务请求。
- Webhook：配置 URL（做 SSRF 防护）和订阅事件，投递带请求头 `X-Nex-Event`、`X-Nex-Delivery`、`X-Nex-Timestamp`、`X-Nex-Signature`（`hex(HMAC-SHA256(secret, timestamp + "." + body))`），单次超时 5 秒，最多尝试 5 次（失败后依次等待 1 分钟、5 分钟、30 分钟、2 小时），投递记录保留 30 天，可手动重试和测试；Webhook 密钥形如 `whsec_...` 可重置，库里加密存放。
- 接口文档：`GET /openapi.json`（OpenAPI 3.0.3，原始 JSON，不套统一响应体）和 `GET /openapi/routes`（运行时路由清单），权限 `openapi:list`；停用的模块不出现在文档里。
- MCP 入口：`POST /mcp`（权限 `mcp:list`），支持 JSON-RPC `initialize`、`ping`、`tools/list`、`tools/call` 和通知；协议版本 `2025-03-26`。GET 工具直接调用，显式注册的写工具走服务端确认流程（当前消息模块注册 `message_mark_read`），不会开放任意写路由或任意 URL。实际调用重新经过原路由登录、权限与租户检查，应用签名不能作为用户 Bearer 凭据复用。`GET /mcp/tools` 保留目录。
- MCP 会话：初始化返回 `Mcp-Session-Id`，后续携带该头；`DELETE /mcp` 删除会话。元数据与每会话最多 4 个并发请求槽位存在配置缓存，多实例须共享 Redis / Valkey；固定有效期取 15 分钟与初始化凭据剩余寿命的较短者，不随活动或刷新延长，且绑定具体身份与凭据。每实例最多跟踪 1024 会话、64 并发请求；请求最长 30 秒，缓存异常拒绝并取消相关请求上下文。会话 ID 不能替代认证。
- MCP 写确认：先返回 `confirmationId` 和浏览器确认地址；用户通过浏览器 `/admin/mcp/confirmations/:id` 查看，并以会话 JWT 和本地密码调用 `POST /mcp/confirmations/:id/approve`，确认有效期 5 分钟。PAT / 应用签名不能用于浏览器批准；批准后以相同工具和 `confirmationId` 再调用，服务端重新核验并原子消费，客户端 `confirmed` 不能绕过。支持 JSON 或最终单条 SSE 响应封装；不支持批量请求、GET 长连接、事件重放、进度流或转发上游工具 SSE。真实 Redis 多实例与浏览器链路仍需验收。

## 4. 源码插件与授权机制（简述）

插件以源码包交付：安装 = 拷文件 + 重新编译；`edition: free` 不校验授权，`edition: pro` 需要离线签名的授权文件（`data/licenses/<id>.lic`，ed25519 签名，载荷含插件、客户、签发 / 到期时间，可选域名）。

- 命令：`nexadmin plugin list | install | remove | keygen | sign | revoke`（用法见 `nexadmin` 的 usage；`sign` / `revoke` 是发行方用的签发与吊销）。
- 校验：启动时逐个校验，有效才挂载路由和菜单；缺失 / 过期 / 被篡改不挂载，插件管理页显示原因；导入授权后尝试激活已编译插件，须检查 `needRestart` 与日志；热挂载失败、官网根路由或启动期认证扩展等仍需要重启核验，不保证全部热激活。运行中每小时复查一次，到期的插件路由返回 403；到期前 30 天在 `GET /plugins` 里带 `expiresSoon`；授权带 `domains` 时校验当前服务域名（精确或 `*.example.com`，来源见《配置参考》第 8 节）；`requires_nexadmin` 在加载时按框架版本校验；发行方可另发签名的吊销清单 `config/license-revoked.json`，序列号命中的授权状态为 `revoked`（路由返回 403，文件变化后无需重启；辅助手段，买家可删除清单）。
- 运行期启停（`plugin:edit`）：插件管理页每张卡片一个开关，`POST /plugins/<id>/enabled`。停用**立刻**关掉该插件的路由（403 + 原因）与侧栏菜单入口，`GET /plugins/active` 也随之剔除；停用清单落在节点本地的 `data/licenses/disabled.json`，与配置 `disabled_plugins` 取并集（配置优先，被配置停用的插件页面上打不开），重启后保持。**做不到的一侧写清楚**：未实现 `plugin.RestartableStarter` 的 worker（当前所有官方插件）被停用后不会在线重新拉起，重新启用会留 `needRestart=true` 且接口与菜单继续不可用，直到重启服务；已建立的 WebSocket/SSE、事件订阅、作业注册同样要重启才干净停掉。多节点不会自动同步开关状态。

- **音频验证码这一格能钉的是「离线哈希字典不可行」，不是「识别命中率」**：读题停顿按 key 抖动（数字间各一段、两遍之间一段，每段 `audioGapLevels` 档），所以同一条答案能合成出 `audioGapLevels^(位数+1)` 种逐字节不同的 WAV（5 位答案 = 4^6 = 4096 种）；想靠「预先存好每种音频的哈希」免听认题，就得为每条答案预存这一整份集合。实测：300 个 5 位真 key 采样得到 289 种不同整串哈希。仍未验、这台机器也验不了的是「机器语音识别命中率 <5%」这条旧判据——它需要 ASR 引擎，本机没有（无 tesseract、无语音模型）；别把它算作本轮的验收项。
- **官网插件的迁移编号有重复（本轮决定不改名）**：`plugins/website/migrations/{mysql,mariadb,postgres}/` 三份里各有两个 019（`019_head_code.sql`、`019_post_metrics.sql`）和两个 020（`020_post_tags.sql`、`020_title_suffix.sql`），现有最高号其实是 `021_post_versions.sql`。不修的原因：迁移台账的版本号就是**文件名**（`core/migrate/discover.go:43`「文件名，同时是版本号」，落库主键 `PRIMARY KEY (scope, version)`，`core/migrate/store.go:118`），改任意一个名字都会让已执行的那条在存量安装上重新变成「待执行」，同一段 SQL 再跑一遍（`ALTER TABLE ... - **插件手写 SQL 全部没有自动化覆盖（2026-11-08 起 Go/前端用例清零）**：全仓 Go/前端自动化用例已整体移除（commit 22ff72c），下列手写 SQL 在任何引擎上都没有会执行它的测试，只能靠人工真库复跑验证：`report`（`plugins/report/query.go:179` 的按方言加反引号构建器、`plugins/report/query.go:240-242` 的 `to_char(...)` / `DATE_FORMAT(...)` 时间分桶、`plugins/report/sources.go:96-167` 的白名单表——是 **7 张**不是 8 张）、`cron`（`plugins/cron/builtin.go:187` 动态 `Exec("DELETE FROM "+table+...)`）、`formbuilder`（`plugins/formbuilder/directory.go:65-67,110-112` 拼表名的 `JOIN`、`plugins/formbuilder/store_sub.go:99` 的 `(? <= 0 OR submission_count < ?)` 谓词）、`audit`（`plugins/audit/callback.go:102,147` 用 `Table(st.Schema.Table)` 动态重查新旧值）、`scim`（`plugins/scim/handler.go:79,144,288,414` 直接 `Table("sys_user")` 读写框架表）、`media`（`plugins/media/service.go:19-22` 的 `EXISTS (SELECT 1 FROM sys_file v ...)` 相关子查询）、`i18n-editor`（`plugins/i18n-editor/plugin.go:197-203` 用 `sys_tenant` 上的 no-op `UPDATE` 当写锁）、`aigateway`（`plugins/aigateway/service.go:312-313` 的 `COALESCE(SUM(...),0)` 聚合）、`website`（`plugins/website/service.go:963`、`plugins/website/taxonomy.go:262` 的动态 `Exec("DELETE FROM ...")`）。`identity` / `codegen` / `imports` / `maps` 没有手写 SQL 片段（只有模型查询），`security` 只剩一条关键词片段（`plugins/security/store.go:134`）。`saml` 自 0.8.0 起有了手写 SQL：`plugins/saml/rolesync.go:104,123` 直查 `sys_role`，`:111,134` 删除、`:137` 插入 `sys_user_role`；001→008 的迁移 DDL 与这几条语句已在一次性 MySQL 8.0.12 与 PostgreSQL 18.6 上实际执行通过（MariaDB 文件与 MySQL 相同，未单独启动 MariaDB）。上面列出的语句在 PostgreSQL / MariaDB 上的正确性仍是**未证明**。

## 5. 角色与数据范围

### 5.1 RBAC

用户 → 角色 → 菜单 / 按钮权限，权限码命名 `模块:动作`；超管（`*`）短路放行；权限每次请求从登录提供者读取最新值，不信令牌里的快照。新增菜单 / 权限点只有超管默认可见，其他角色要到“角色管理”分配。出厂角色：`admin`（超级管理员，内置，不可删除 / 停用 / 改编码，不可被分配）、`operator`、`auditor`、`editor`（默认停用）、`guest`、`secadmin`（演示“不可被分配”）。后五个是演示角色，菜单授权默认留空。

### 5.2 数据范围

角色的 `data_scope` 字段，取值：

| 取值 | 含义 |
| --- | --- |
| `all` | 全部 |
| `deptAndChild` | 本部门及以下（依赖 `sys_dept.path` 物化路径；取不到时退化为本部门） |
| `dept` | 本部门 |
| `self` | 仅本人 |
| `custom` | 自定义部门集合（`sys_role_dept`） |

用户有多个角色时取并集：任一角色是 `all` 即全部；预设范围取最宽的一档；自定义部门与预设展开的部门合并成一个集合。超管恒为全部。操作者自己永远在范围内；“本部门 / 本部门及以下”的用户没有所属部门时视为仅本人。范围用在用户、部门、公告、操作日志、登录日志的读写裁剪（部门的读取裁剪仅在部门管理页带 `scene=manage` 时生效；非超管且范围非“全部”的操作者发公告时，发布对象也受该范围限制）。

### 5.3 角色可分配的三道校验

非超管把角色分配给别人（新增 / 编辑用户、导入用户、角色选项）时，三道校验按顺序独立判断，报告第一个不满足的（`core/roleassign`）：

1. 角色可分配：`assignable=true`，且不是内置超管角色，且权限里不含 `*`。不满足提示“该角色不允许被下级管理员分配”。
2. 权限不超出：角色的权限集合必须是操作者当前权限集合（多个角色取并集）的子集。不满足提示“所选角色的权限超出了你自己的权限范围，不能分配”。
3. 数据范围不更宽：要分配的角色范围不能比操作者的范围更宽。不满足提示“所选角色的数据范围比你的数据范围更宽，不能分配”。判定表（行 = 角色范围，列 = 操作者范围；`全部` 的操作者一律允许）：

| 角色 \ 操作者 | 全部 | 本部门及以下 | 本部门 | 仅本人 | 自定义（集合 S） |
| --- | --- | --- | --- | --- | --- |
| 全部 | 允许 | 拒绝 | 拒绝 | 拒绝 | 拒绝 |
| 本部门及以下 | 允许 | 允许 | 拒绝 | 拒绝 | S 对下级封闭（每个部门的整棵子树都在 S 内）才允许 |
| 本部门 | 允许 | 允许 | 允许 | 拒绝 | 允许 |
| 仅本人 | 允许 | 允许 | 允许 | 允许 | 允许 |
| 自定义（集合 R） | 允许 | R ⊆ 操作者可见部门 | R ⊆ {本部门} | 仅 R 为空才允许 | R ⊆ S |

操作者的权限与数据范围实时从库里读取。公开包 `nexadmin/core/roleassign`、`nexadmin/core/datascope` 可供业务模块直接使用。

## 6. 租户额度与到期强制

租户由“租户管理”维护，字段含状态（`active` / `suspended` / `expired`）、到期时间（空为永不过期）、套餐、域名，以及可覆盖套餐的用户数 / 角色数 / 存储（MB）额度；额度为 0 表示不限。租户自己的额度优先，其次取套餐。出厂会写入 12 个演示套餐和若干演示租户。

到期与停用：

- 状态判定：`suspended` / `expired` 直接拒绝；有到期时间且已过期时，若在宽限期内放行（`StateGrace`），超出宽限期拒绝。宽限天数取系统参数 `tenant.grace_days`（默认 0），到期提醒天数取 `tenant.expire_warn_days`（默认 15，0 为不提醒）。
- 强制点：登录、刷新令牌、第三方登录签发令牌前都校验；已登录的非超管请求（含个人访问令牌和应用签名调用）在每次请求的租户中间件里校验，登出放行，让前端能清理会话；被拒绝返回 HTTP 403，`reason: TENANT_EXPIRED`。平台超管和默认租户（不受管）不受影响。
- 到期提醒：`GET /auth/me` 在到期前 `expire_warn_days` 天内（含宽限期）带 `tenantExpireSoon`（到期时间与剩余天数）。
- 续期 / 启停：`PUT /tenants/:id/renew`、`PUT /tenants/:id/status`（权限 `tenant:update`）；租户信息有 30 秒进程内缓存兜底，修改后会通过 `core/cluster` 广播失效事件，其他实例通常立即生效，广播丢失时最多延迟 30 秒（多实例细节见《部署与运维指南》第 10 节）。

额度强制（超出返回 HTTP 403，对应 `reason`）：

| 额度 | 强制位置 | reason |
| --- | --- | --- |
| 用户数 | 新增用户、导入用户、第三方登录自动建号（同一事务内先锁租户行再统计，并发不超额） | `TENANT_QUOTA_USERS`（“用户数已达套餐上限（N 个），无法继续新增”） |
| 角色数 | 新增角色（同上，先锁租户行再统计） | `TENANT_QUOTA_ROLES`（“角色数已达套餐上限（N 个），无法继续新增”） |
| 存储 | tus 创建会话时按声明长度原子预占，将实际用量与进行中预占合并检查；完成、取消等路径释放预占，过期预占按租约清理（`modules/file/usage.go`） | `TENANT_QUOTA_STORAGE`；受限上传要求缓存实现 `cache.Lease`，不支持则拒绝；多实例须使用共享缓存，真实 Redis 并发仍待验收 |
| AI 开关 | 租户可被单独关闭 AI（`sys_tenant.ai_enabled`）；AI 网关在 `/ai/*` 调用时检查，平台超管与默认租户不受限 | `TENANT_AI_DISABLED` |
| AI 每日调用次数 | 套餐 `ai_daily_quota`（0 为不限），租户可覆盖（空为沿用套餐，0 为不限）；`filter`、`translate`、`write` 共用同一份次数，平台超管与默认租户不受限 | `TENANT_QUOTA_AI` |

套餐还可以限定菜单范围：用户的有效权限会与套餐菜单对应的权限取交集（套餐菜单为空则不限制）。跳过租户隔离的平台级操作（超管端）不受额度限制。

### 6.1 租户自助、品牌与开通初始化

- 我的租户：`GET/PUT /tenant-self` 只作用于调用者所在租户，不能读改其他租户。可查看套餐、到期、有效额度与用量、近 30 天切片；可维护企业名称、联系人、电话、邮箱与 logo；租户名称 / 域名 / 套餐 / 额度 / 到期仍由平台管理。平台超管与默认租户没有租户记录，返回 404，前端显示“当前账号不隶属任何租户”。
- 品牌：`GET /settings/public` 在按域名或请求头解析到租户时，用 `sys_tenant.name` / `sys_tenant.logo_url` 覆盖站点名与 logo，登录页与侧栏随域名生效；两者留空则沿用平台站点设置。
- 开通初始化：新增租户并勾选创建管理员时，在同一事务内创建根部门“总部”、默认岗位与“普通员工”角色（工作台 / 个人中心 / 关于，数据范围仅本人，非内置角色），避免新租户没有组织骨架。
- 用量切片：`sys_tenant_usage_daily` 按 `(tenant_id, day)` 唯一；租户管理员每次打开“我的租户”幂等写入当天一行，趋势最多展示近 30 天，首日只有一个点。
- 按租户限流：`ratelimit.tenant_api`（默认 `limit: 0` 即关闭）按租户给 `/api/v1` 全部后台接口计数，避免单个租户的异常流量拖垮其它租户；解析不到租户的请求不计入。

## 8. 关键词搜索的大小写折算

- 策略：**凡是用户手输关键词的筛选，一律写成 `LOWER(<列>) LIKE LOWER(?)`，两侧都折叠**。原因是方言差：MySQL / MariaDB 这儿的 `utf8mb4` 排序规则不区分大小写，`col LIKE '%Abc%'` 天然能命中；PostgreSQL 的 `LIKE` 区分大小写，所以在这次改动之前，搜索框里带一个大写字母在 PG 部署上静默返回 0 行、在 MySQL 上却搜得到（三引擎都是受支持引擎，不能只按 MySQL 的行为验收）。也不能改用 `ILIKE`——MySQL / MariaDB 没有这个操作符。插件侧的标准写法见 `plugins/report/query.go:423`、`plugins/formbuilder/directory.go:98`、`plugins/im/service.go:507`；内置模块侧是把模式先在 Go 里 `strings.ToLower` 再写成 `LOWER(<列>) LIKE ?`（`modules/system/user/service.go:60-62`、`modules/system/config/service.go:107-109`、`modules/system/dict/service.go:73-78`），折叠发生在绑定值那一侧，口径相同。
- 刻意**不**折叠的豁免（大小写对这些站点无意义，它们匹配的不是人随手打的关键字）：部门的物化路径前缀筛选 `path LIKE ?`，绑进去的值形如 `/1/4/`（`modules/system/dept/scope.go:30`、`modules/system/dept/service.go:167,211,218,221,378`、`modules/system/user/scope.go:55` 的 `dept_id IN (SELECT id FROM sys_dept WHERE path LIKE ?)`、`core/datascope/datascope.go:99`）；官网「缺译文」筛选的 `i18n_json NOT LIKE ?` 匹配的是配置里的语言 code，两侧同源（`plugins/website/service.go:587-589`，已按标注约定写了 `nexadmin:like-exempt` 注释和理由）。注意 IM 的标签包含匹配**不在豁免之列**：`plugins/im/service.go:507` 写的是 `LOWER(CONCAT(',', tags, ',')) LIKE LOWER(?)`，两侧都折叠。
- 约定：确有价值、不受大小写影响的例外，在调用行或其前三行加 `nexadmin:like-exempt` 注释并写明理由（`plugins/website/service.go:587-589` 已按此标注）。已知盲区是把 `LIKE` 片段拼在 `Where` 之外再以变量传入的写法（`plugins/report/query.go` 的 filterSQL），那里要按整句 SQL 人工核对折叠形状。此前这套约定由 `TestPluginsLikeFiltersFoldCase` / `TestLikeCaseFoldGateRepo` 等闸守着（基线：检查 47 条、豁免 11 条、违规 0），用例已随 2026-11-08 清理移除。
